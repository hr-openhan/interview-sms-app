# 채용 대시보드 (이력서 검토 · 공고 · 면접 문자 발송)

지원자 이름·연락처를 입력하고 문자 양식(17종)을 고르면, 문자코리아(smsko.co.kr) API를 통해 실제 문자가 발송됩니다.

## 1. 준비물

- Node.js 18 이상 (https://nodejs.org 에서 설치)
- 문자코리아 계정의 **아이디, API 인증키(sec_apiKey), 등록된 발신번호**
  - 로그인 후 "내정보 > API연동" 메뉴에서 확인/발급

## 2. 설치

터미널(또는 CMD)에서 이 폴더로 이동한 뒤:

```bash
npm install
```

## 3. API 키 설정

`.env.example` 파일 이름을 `.env` 로 바꾸고, 문자코리아에서 발급받은 값을 입력하세요.

```
SMSKO_USER_ID=문자코리아_로그인_아이디
SMSKO_API_KEY=API_인증키(sec_apiKey)
SMSKO_SENDER=등록된_발신번호(예: 0212345678, 하이픈 없이)
PORT=3000
```

> 발신번호는 반드시 문자코리아에 사전 등록되어 승인된 번호여야 발송이 됩니다.

## 4. 실행

```bash
npm start
```

브라우저에서 `http://localhost:3000` 접속.

## 5. 사용 방법 (문자 보내기)

화면 맨 위 탭은 **이력서 검토 → 문자 보내기 → 양식 관리** 순서이고, 처음에는 이력서 검토가 열려요. 문자를 보내려면 **"문자 보내기" 탭**을 누르세요.

1. 지원자 이름, 연락처 입력
2. 문자 양식 선택 (팀장면접, 대표면접, 불합격, 최종합격 등 17종 — 기존 발송 이력에서 그대로 가져온 문구)
3. 양식에 면접 일정이 필요한 경우 일정 입력란이 나타남 → 입력
4. 오른쪽 미리보기에서 실제 발송될 문구 확인 — **미리보기 안의 텍스트는 직접 클릭해서 수정할 수 있습니다.** 수정하면 "문자 보내기"를 눌렀을 때 자동 생성된 내용이 아니라 수정한 내용 그대로 발송됩니다. "자동 생성 내용으로 되돌리기" 버튼으로 언제든 원래 문구로 되돌릴 수 있습니다
5. "문자 보내기" 클릭 → 문자코리아 API로 실제 SMS/LMS 발송 (내부적으로 토큰 발급 후 메시지 전송 2단계로 처리됩니다)

## 6. 메모 및 발송 이력

발송 화면 하단에 **메모** 입력란이 있습니다. 여기 적은 내용(예: "강남팀", "재면접 대상")은 **문자 내용에는 포함되지 않고**, 서버의 `history.json` 파일에 내부 기록용으로만 저장됩니다.

화면 맨 아래 **발송 이력** 표에서 최근 발송 건들을 일시/이름/연락처/양식/**면접 제안 일시**/메모/성공여부와 함께 확인할 수 있습니다.
- **면접 제안 일시**: 문자 보낼 때 "면접 일정 / 세부 내용"란에 입력했던 내용이 그대로 표시됩니다
- **검색**: 이름 또는 연락처로 검색 가능
- **월별 필터**: 드롭다운에서 특정 월만 골라 보기 가능
- **정렬**: 날짜순/가나다순 전환
- **삭제**: 각 행 왼쪽 체크박스로 원하는 만큼 선택한 뒤 "삭제 (N)" 버튼으로 한 번에 지울 수 있습니다 (하나만 선택해도 됩니다)
- **수기로 추가**: 앱을 거치지 않고 다른 방법(직접 문자, 전화 등)으로 이미 연락한 건도 "+ 수기로 추가" 버튼으로 이력에 기록만 남길 수 있습니다 (실제로 문자가 발송되지는 않습니다). 보낸 문자 내용도 함께 적어둘 수 있습니다
- **보낸 문자 확인**: 이력 표의 **양식명(파란 밑줄 글자)을 누르면** 실제로 발송된 문자 전문, 받는 사람, 발송일시, 결과(실패 시 사유)를 팝업으로 볼 수 있습니다. 미리보기에서 직접 수정해서 보낸 경우에도 수정된 내용 그대로 저장됩니다. (문자 내용 저장 기능이 추가되기 이전에 발송한 건은 내용이 없다고 안내됩니다)
- **일정 등록 연동**: 각 행의 "일정 등록" 버튼을 누르면 그 지원자의 이름/연락처가 자동으로 채워진 채 아래 "면접 일정 등록" 폼으로 화면이 이동합니다
- **참석여부(미응답/참석/불참석)**: 각 행에서 지원자의 면접 참석 여부를 바로 선택할 수 있습니다. 선택 즉시 저장됩니다 (참석 여부는 여기서만 관리하며, 면접 일정 쪽에는 따로 표시되지 않습니다)

## 7. 양식 수정하기

이제 터미널이나 메모장 없이, **앱 화면의 "양식 관리" 탭**에서 바로 양식을 추가·수정·삭제할 수 있습니다.
- 위쪽 드롭다운에서 조회할 양식을 선택하면 내용이 아래에 표시됩니다 (한 번에 하나씩만 보여서 스크롤이 길어지지 않습니다)
- "수정" 클릭 → 이름/본문 편집 → "저장" (또는 "취소"로 되돌리기)
- 지원자 이름이 들어갈 자리는 `{{name}}`, 면접 일정이 들어갈 자리는 `{{date}}` 로 입력

## 8. 면접 일정 관리

**"문자 보내기" 화면 안, 발송 이력 아래**에서 확정된 면접 일정을 별도로 기록하고 관리할 수 있습니다 (별도 탭이 아니라 같은 화면에서 쭉 이어져 보입니다).
- 지원자가 문자에 회신해서 면접일이 확정되면, 이름·연락처·확정 일시·**팀**·**면접진행자(선택형)**·**면접장소(선택형)**·비고를 입력해 등록
- **확정 일시 입력**: 연도(2025/2026/2027, 기본값 2026)·월·일은 드롭다운으로 고르고, 시·분은 직접 숫자로 입력합니다 (예: 14 : 30)
- **팀**은 아래 10개 중 선택(가나다순): 경영지원팀, 그로잉업팀, 글로벌비즈니스팀, 마케팅팀, 브이팀, 온라인팀, 와우서비스팀, 제품디자인팀, FC팀, SCM팀
- **면접진행자**는 아래 8명 중 선택(가나다순): 니콜, 로이, 마리네뜨, 안나, 카라, 케빈, 한스, 헨리
- **면접장소**는 오즈센터, 오픈한웍스 중 선택 (구체적인 회의실 호수는 비고에 적어주세요, 예: "3층 회의실")
- **면접 일정 목록**: 전체 일정을 날짜순으로 보여주는 표입니다 (일시/이름/연락처/팀). **이름으로 검색**하거나 상단 필터로 **팀** 별, **기간(전체/1일/1주일/1개월 — 오늘부터의 기간)** 별로 좁혀볼 수 있습니다. "상세" 버튼을 누르면 아래 상세보기로 이동합니다
- 상세보기에서 "수정" 클릭 → 연락처/일시/팀/면접진행자/면접장소/비고 편집 → "저장" (또는 "취소") — 참석 여부는 여기가 아니라 발송 이력에서 관리합니다
- "삭제"로 일정 제거
- **일정 변경/취소 관리**
  - 상세보기 → "수정"에서 **면접 일시를 바꾸면** 이전 일시 → 새 일시가 **변경 이력**으로 자동 기록됩니다 (사유를 적으면 함께 저장).
  - **상태를 "취소"로 바꾸고 저장**하면 취소 일시·사유가 기록되고, 목록에서 흐리게(취소선) + "취소" 배지로 표시됩니다. 취소된 일정은 "오늘의 면접"에서 빠집니다. 다시 "예정"으로 돌리면 취소 정보가 지워집니다.
  - 목록에서 일시가 변경된 일정은 "변경" 배지가 붙고, 상단 **"전체상태" 필터**로 `진행 예정 / 변경된 일정 / 취소된 일정`만 모아서 정리해 볼 수 있습니다.
- **오늘의 면접**: 맨 아래에 "2026년 9월 10일 오늘의 면접일정"처럼 오늘 날짜가 제목에 표시되며, 오늘 예정된 면접만 시간·이름·팀·면접진행자·면접장소로 간단히 보여줍니다. 이름을 클릭하면 위 상세보기로 이동합니다

## 9. 구글캘린더에 추가

상세보기의 **"구글캘린더에 추가"** 버튼을 누르면 구글캘린더 새 창이 열리며 일정 내용이 자동으로 채워집니다. 별도 API 키나 로그인 연동 설정 없이 바로 동작하며, "저장"만 누르면 등록됩니다.
- 제목: 팀이 **SCM팀**이면 `SCM팀 면접 - 이름`, 그 외 팀이면 위치 표기를 위해 `[3F] 팀이름 면접 - 이름`
- 제목만 자동으로 채워지고, "설명" 칸은 비워둡니다 (위치도 채우지 않습니다)
- 시간: 등록하신 면접 일시부터 기본 1시간짜리 일정으로 생성됩니다
- **참석자 자동 추가**: 면접진행자가 아래 목록에 있으면 `{아이디}@openhan.kr` 이메일로 자동 초대됩니다. (헨리는 이메일 매핑이 없어 자동 추가되지 않습니다 — 필요하시면 알려주세요)
  - 니콜=nicole, 로이=loi, 카라=kara, 한스=hans, 마리네뜨=marinette, 케빈=kevin, 안나=anna
- **캘린더 선택**: 특정 캘린더(예: "미팅&행사&북클럽")에 저장하고 싶다면, 열린 화면에서 저장 전에 캘린더 선택 드롭다운을 한 번 눌러 고르시면 됩니다 (자동 지정은 구글이 막아둔 기능이라 이 단계만 수동으로 필요합니다)
- **초대 메일 관련**: 참석자가 추가되어 있어도, 구글캘린더 저장 화면에서 "알림 보내기"를 선택하지 않으면 이메일이 따로 발송되지 않습니다. 지원자 이메일은 수집하지 않으므로 지원자에게는 애초에 메일이 가지 않습니다

## 문자에 보낼 수 없는 글자 (errCode 2039 "발송불가문자")

국내 문자 발송은 EUC-KR 계열 글자만 보낼 수 있어서, 아래 글자가 섞이면 문자코리아가 `errCode 2039 발송불가문자`로 거부합니다.
특히 노션·카카오톡·웹페이지에서 **복사/붙여넣기** 하면 눈에 안 보이는 특수 공백(NBSP, `U+00A0`)이 같이 딸려오는 경우가 많습니다.

이 앱은 보낼 때 아래처럼 처리합니다.

| 종류 | 처리 |
|---|---|
| 눈에 안 보이는 특수 공백(NBSP 등) | 일반 공백으로 **자동 변환** |
| 폭 없는 숨은 글자(ZWSP, BOM 등), 제어 문자 | **자동 삭제** |
| 긴 줄표 `—` `–`, 글머리 `•` | `-`, `·` 로 **자동 변환** |
| 이모지(😊), `✔`, `❤` 등 | 바꿀 수 없으므로 **발송 전에 막고** 어떤 글자인지 알려줌 (문자코리아 호출/요금/실패 기록 없음) |

- 미리보기 아래에 **노란색 안내**(자동으로 바뀌는 글자) 또는 **빨간색 경고**(직접 지워야 하는 글자)가 미리 표시됩니다.
- 발송에 성공하면 "자동으로 바꿔서 보냈어요: …" 라고 어떤 글자를 바꿨는지 알려줍니다.
- 지원자 이름, 문자 제목, 연락처(숫자만 남김)에도 같은 정리가 적용됩니다.
- 현대 한글 11,172자는 모두 허용합니다 (드문 글자가 들어간 이름을 잘못 막지 않기 위해서).

## 9-2. 이력서 검토 (AI 평가)

화면 맨 위 탭은 **공고 관리 → 면접 관리 → 문자 보내기 → 승진·경력 관리 → 양식 관리** 순서예요(면접 관리가 문자 보내기 왼쪽에 있어요. 승진·경력 관리는 권한이 있는 사람에게만 보여요, 9-25). **"공고 관리" 탭** 안에 **"이력서 검토"**와 **"공고 만들기"** 두 하위 버튼이 있고, 처음에는 이력서 검토가 열려요(다시 누르면 직전에 보던 화면을 열어요). **"이력서 검토" 화면**에서 이력서 한 건을 올리거나 붙여넣으면, **공통 인재상 + 선택한 확정 공고의 공고문 + 100점 평가표**를 기준으로 Claude(Anthropic AI)가 1차 평가를 해줍니다. 공고는 **"공고 만들기" 화면**(9-6)에서 만들어요(파일로 한꺼번에 가져올 수도 있어요, 9-24). 점수는 검토 우선순위를 잡는 참고이고, **합격·탈락은 사람이 정합니다.**

**1) 회사 정보 · 공고** (처음엔 문서의 내용이 기본값으로 들어 있어요)
- **회사 소개(사명·비전)** + **공통 인재상 10가지**: 노션 「사명, 비전, 인재상」 페이지의 내용이 기본값이에요. 이력서 검토 탭에서 **"회사 소개 (사명 · 비전) 보기·수정"**, **"공통 인재상 보기·수정"**은 "평가표 보기"와 같은 **접었다 펴는 상자**예요(처음엔 접혀 있어요). 상자를 **누르면 펴지고, 다시 누르면 접혀요.** 펴면 글칸이 내용 길이만큼 늘어나서 **안쪽 스크롤바 없이 한 번에 다 보여요**(글을 고치는 중에 길어져도 따라 늘어나요). 평소에는 **잠겨 있고**, 상자 아래의 **"✏️ 수정"**을 누르면 두 상자가 펼쳐지며 고칠 수 있어요. 고친 뒤 **"저장"**(또는 "취소", "처음 내용으로 되돌리기")을 눌러야 반영돼요. 수정 중에 다른 탭에 갔다 와도 쓰던 글은 지워지지 않고, 저장하지 않은 채 평가를 시작하면 "저장하지 않은 수정은 평가에 쓰이지 않아요"라고 한 번 물어요. 글자 수 제한은 회사 소개 4000자, 인재상 8000자예요. AI는 이력서에서 실제 근거가 확인되는 인재상 항목만 "인재상과 연결되는 근거"로 보여줘요.
- **공고**: "공고 만들기" 탭에서 팀 → 포지션 → 근무 조건 순서로 공고문을 만들고 **확정**해요 (아래 9-6). 평가는 확정된 공고의 공고문을 기준으로 해요.

**2) 평가표 (총 100점)** — "평가표 보기"에서 확인. 공고의 **채용 유형(경력직 / 신입직)**에 따라 평가표가 달라져요. 항목마다 **S/A/B/C 기준**이 있고(예: 유사 경력 S 30점·A 24점·B 18점·C 12점 이하), 그 사이 점수도 줄 수 있어요.

**경력직** (기본)
| 평가 영역 | 배점 |
|---|---|
| 유사 경력 (공고 업무와의 일치·핵심 성과) | 30 |
| 공고문 적합도 (필수·우대 요건 충족) | 20 |
| 성과·문제 해결 근거 | 15 |
| 인재상·태도 근거 | 15 |
| 경력 연차 (공고의 목표 연차와의 부합) | 10 |
| 학력·전공 (직무 관련 전공·교육) | 10 |

**신입직**
| 평가 영역 | 배점 |
|---|---|
| 직무 관련 프로젝트·자기소개서 | 40 |
| 공고문 적합도 | 20 |
| 학력·전공 | 20 |
| 자격증·교육 | 20 |

**점수와 탈락의 관계**: 학력·전공 점수도 총점에는 들어가지만, **"검토 우선순위"(적극 추천·추천·보류)는 학력을 뺀 점수로만** 정해요(환산 75점 이상 적극 추천, 55점 이상 추천, 그 미만은 보류). AI가 "비추천"이라고 해도 쓰지 않고, 점수가 아무리 낮아도 탈락으로 표시하지 않아요. 노션의 추천 칸 `REJECT`도 자동으로 고르지 않아요(사람이 직접 고르는 값). **필수 요건 체크**(충족·부분 충족·미충족·확인불가)는 점수와 별개의 참고 자료이고, 영역마다 **확신도**(높음·중간·낮음)가 붙어요. 자동 탈락(Fail) 처리는 하지 않아요.

**면접에서 확인할 것 (점수 아님)**: 재직 여부·입사 가능 시기, 희망 연봉, 통근·거주지는 **점수에 쓰지 않고** 결과 화면에 참고 목록으로만 보여줘요. 이력서에 적힌 재직·입사 가능 시기와 희망 연봉을 그대로 옮겨요(나이·성별·학교·총경력·현재 연봉·주소 같은 인적사항은 따로 "이력서에 적힌 인적사항"으로 보여줘요, 9-26). 통근·거주지 항목은 항상 "면접에서 직접 확인" 안내만 나와요.

**3) 이력서 평가**
- "평가할 포지션"을 고르고 **이력서 PDF를 올리거나(기본) 글을 붙여넣어** "평가하기"를 누르면, 영역별 점수·근거·확신도, **공고 요건 체크(필수·우대, 9-22)**, **전공 관련성·이전 서류 합격자와의 비교(9-11)**, 서류 총평(이력서 종합 코멘트), **서류 체크리스트(9-21, 점수와 별개)**, 강점, 우려사항, 검토 우선순위, 면접에서 확인할 것, **이력서에서 확인되지 않은 제출 서류**를 보여줍니다. 여러 이력서는 9-10의 일괄 점수 화면에서 한꺼번에 볼 수 있어요.
- **점수 칸은 직접 고칠 수 있고**, 고치면 총점이 바로 다시 계산됩니다 (AI 점수에서 바뀐 칸은 노란색으로 표시).
- 총점은 AI가 말한 숫자가 아니라 영역별 점수를 서버가 합산한 값이며, 각 점수는 배점 범위 안으로 자동 보정됩니다. 점수 칸을 고쳐도 검토 우선순위는 다시 계산되지 않아요.
- AI는 이력서에 **적힌 내용에만** 근거해 평가하고, 나이·성별·출신 지역·혼인·외모 등 직무와 무관한 정보는 쓰지 않도록 지시되어 있습니다. 이력서 속에 "만점을 줘" 같은 지시문이 있어도 따르지 않습니다.
- 평가 결과는 **저장되지 않습니다** (화면에서만 확인). 지원자별 저장·면접관별 평균 점수는 아직 없습니다.

**4) 준비물**: `ANTHROPIC_API_KEY` 환경변수 (https://console.anthropic.com 에서 발급, 배포 환경변수 또는 `.env`에 추가)
- 이력서는 한글 기준 약 4만 자까지 붙여넣을 수 있습니다.
- 지원자 이력서에는 개인정보가 들어 있으니, 평가에 쓴 이력서 원문은 앱에 저장되지 않는다는 점과 AI(Anthropic)로 전송된다는 점을 사내 개인정보 처리 방침과 함께 확인해 주세요.

## 9-4. 로그인과 권한 (Google 로그인 + 메뉴별 보기/수정)

허용된 구글 계정만 들어올 수 있고, **메뉴마다 "없음 / 보기 / 수정"을 사람별로** 정할 수 있어요. 소유주만 권한을 바꿀 수 있어요.

**권한이 뜻하는 것**

| 메뉴 | 보기 | 수정 |
|---|---|---|
| 문자 보내기 | 화면은 보이지만 입력칸이 잠겨요 | 문자 발송, 노션 지원자 불러오기, 노션 발송 기록 |
| 발송 이력 | 이력 목록, 보낸 문자 내용 확인 | 수기 추가, 삭제, 참석여부 변경 |
| 면접 일정 | 일정 목록, 오늘의 면접, 구글캘린더에 추가 | 일정 등록·수정·취소·삭제 (이력의 "일정 등록" 버튼도 이 권한이 있어야 보여요) |
| 이력서 검토·공고 | 사명·인재상·평가표 보기(읽기), 공고 조회, 면접 관리 목록 보기(노션 값 읽기) | **사명·인재상 수정·되돌리기**, 공고 만들기·확정·삭제, 팀 직무 참고·팀별 근무지·**팀이 맡은 브랜드·공고 안내 수정**, AI 평가(합격자 참고 포함), **여러 이력서 점수 보기**, 노션 지원자 등록, 지원자 관리에서 합격 여부·면접 일정 수정(노션에 저장) |
| 양식 관리 | 양식 내용 보기 | 양식 추가·수정·삭제 |

- 권한이 없는 메뉴는 화면에서 아예 사라지고, 화면을 우회해서 직접 요청해도 **서버가 다시 확인해서 막습니다.**
- **소유주는 항상 모든 권한**을 가지고, 삭제하거나 낮출 수 없어요. 소유주만 "권한 관리"를 할 수 있어요 (수정 권한을 다 가진 일반 사용자도 불가).
- 소유주가 권한을 바꾸거나 사람을 삭제하면 **이미 로그인한 사람에게도 바로(최대 10초 안에) 적용**돼요.
- 문자 발송·AI 평가·지원자 정보가 걸린 모든 기능이 같은 권한 규칙을 따라요. 새로 만든 API는 기본적으로 소유주만 쓸 수 있게 막혀 있어요.

**왼쪽 하단**의 사용자 도크에서 로그아웃하고, 소유주는 **⚙ 권한 관리**에서 구글 이메일을 추가하고 메뉴별 권한을 정해요. (바꾸면 바로 저장돼요)

## 9-5. 노션 연동 (채용 지원자 DB)

노션 **「🧐 진행중 채용」** DB와 연결해서 아래 3가지를 할 수 있어요. (로그인 보호가 켜져 있어야 해요 — Google 로그인 또는 `APP_PASSWORD`)

1. **이력서 평가 → 노션에 지원자 등록**: 이력서 검토 결과 아래 "노션에 지원자 등록"에서 이름·연락처·팀명·지원채널·면접상태·추천을 확인하고 등록합니다.
   - 노션에 들어가는 값: 이름, 전화번호, 팀명, 지원직무, 지원채널, 입사지원일, 면접상태(기본 서류합격), **종합점수(사람이 확인해 고친 총점, 100점 만점)**, 추천(AI 의견 → PASS/BORDERLINE/REJECT, 고칠 수 있음), 평가 요약(영역별 점수·총평·강점·우려), 평가일시
   - 노션의 `경험·역량`, `성장 잠재력`, `인재상 적합성`, `직무 적합성`, `AI 의심도` 칸은 이 앱의 평가표와 1:1로 대응하지 않아 **건드리지 않습니다.**
   - 같은 연락처(없으면 같은 이름)가 이미 있으면 확인창을 띄워 중복 등록을 막습니다.
2. **노션 지원자 불러오기**: 문자 보내기 화면의 "📋 노션에서 지원자 불러오기"에서 이름 검색/면접상태 필터로 찾아서
   - **문자 보내기**: 이름·연락처가 채워집니다.
   - **일정 등록**: 이름·연락처·팀·구분(1차/2차/채용과제)·면접일이 채워집니다. (노션 팀명 `글로벌팀`→`글로벌비즈니스팀`, `와우팀`→`와우서비스팀`으로 맞춰요)
3. **문자 발송 후 노션 기록**: 노션에서 불러온 지원자에게 문자를 보내면, 노션 카드의 `면접 문자 안내`가 **"문자 발송 완료"**, `면접연락`이 발송 시각으로 기록됩니다. (보내기 전 체크박스로 끌 수 있고, 이름을 고치면 연결이 끊겨요. 노션 기록이 실패해도 문자 발송에는 영향이 없습니다.)

### 연결하는 방법 (처음 한 번)
1. https://www.notion.so/profile/integrations 에서 **새 연동(Internal)** 을 만들고, 권한은 **콘텐츠 읽기/업데이트/삽입**을 켭니다. 만든 뒤 보이는 **시크릿(secret_…)**을 복사하세요.
2. 노션의 「진행중 채용」 DB 페이지 오른쪽 위 **••• → 연결(Connections) → 방금 만든 연동 추가**
3. Vercel 환경변수에 `NOTION_TOKEN`(복사한 시크릿)과 `APP_PASSWORD`를 추가하고 **재배포**
4. 이력서 검토에서 평가를 한 번 돌려보면 "노션에 지원자 등록" 폼이 보이면 연결 성공이에요. 안 보이면 이유가 화면에 한국어로 나옵니다 (토큰 오류 / DB에 연동 미연결 / 칸 이름 변경 등).

> 노션 DB의 **칸 이름이나 종류를 바꾸면** 연동이 멈출 수 있어요 (이름, 전화번호, 팀명, 지원직무, 지원채널, 입사지원일, 면접상태, 종합점수, 추천, 평가 요약, 평가일시, 면접일_1차, 면접일_2차, 면접 문자 안내, 면접연락). 이 경우 화면에서 어떤 칸이 문제인지 알려줍니다. 노션에 없는 팀명/면접상태 같은 값은 선택지가 자동으로 새로 생기지 않도록 등록 전에 막아요.

## 9-6. 공고 만들기 · 확정 · 조회 (팀 → 포지션 → 근무 조건 → 공고문)

**"공고 만들기" 탭**(이력서 검토 바로 옆)에서 공고문을 만들고 **확정**하면, 그 공고가 **"이력서 검토" 탭**에서 이력서 평가의 기준이 돼요. 이력서 검토 탭에는 공고 만들기·조회가 없고, 공고 만들기 탭에는 이력서 평가가 없어요. (둘 다 "이력서 검토·공고" 권한으로 보이고, 권한이 "보기"뿐이면 공고 조회만 할 수 있어요)

**만드는 순서**
1. **① 팀**은 **문자 보내기·면접 일정과 같은 11개 팀 중에서만** 고를 수 있어요(경영지원팀·그로잉업팀·글로벌비즈니스팀·마케팅팀·브이팀·온라인팀·와우서비스팀·제품디자인팀·제품생산팀·FC팀·SCM팀). 직접 입력은 없어요. 인디비주엘·우일신 같은 **브랜드는 팀이 아니라 "팀이 맡은 브랜드"**로 따로 적어요(아래). 예전 기본 공고에만 있던 팀(글로벌팀·포토)은 새 공고에서 고를 수 없고, 조회 필터에만 남아 있어요. 그 팀의 예전 공고는 "수정"으로 열어 면접 일정의 팀으로 옮겨 저장하세요(팀을 그대로 두고 다른 내용만 고치는 것도 돼요). 한 번 옮기면 다시 예전 팀으로는 못 돌아가요.
2. **② 포지션**은 직접 입력하세요. 그 아래 **채용 유형**(경력직/신입직)을 고르면 이력서 평가표가 그에 맞게 바뀌어요(기본은 경력직). 한 번 저장한 포지션은 다음부터 같은 칸에서 골라 쓸 수 있어요. 이미 만든 포지션이면 "이전 공고 불러오기"로 지난 공고를 바탕으로 고쳐 쓸 수 있어요. 팀장·팀원을 같이 뽑으면 "그래픽 전문가 (팀장/팀원)"처럼 포지션 이름에 함께 적으세요.
3. **③ 근무 조건**
   - **근무지**: 처음부터 `서울 강남구 강남대로100길 37`이 채워져요(층수는 적지 않아요). **SCM팀과 와우서비스팀**은 남양주 물류센터(`경기 남양주시 진접읍 경복대로바람골길 42-36`), 나머지 팀은 모두 강남이에요. 팀마다 다른 값이 필요하면 근무지를 쓴 뒤 **"이 팀 근무지를 기본값으로 저장"**을 누르면 다음부터 그 팀을 고를 때 자동으로 채워져요.
   - **고용 형태 · 수습·근무 기간**: 기본은 정규직 · 수습 3개월이에요. 정규직이면 공고에 "정규직 (수습 3개월)", 계약직·인턴 등이면 "근무 기간 N개월"로 적혀요.
   - **접수 시작일·마감일**: 처음엔 오늘부터 **2개월 뒤**까지 채워지고, 시작일을 바꾸면 마감일이 따라가요(마감일을 직접 고치면 그대로 둬요). 공고마다 직접 정해요.
   - **포트폴리오 안내**: 디자인·포토 같은 직무(제품디자인팀, 또는 포지션에 디자인·포토·그래픽·영상·촬영·비주얼 등이 들어간 경우)는 자동으로 켜지고, 물류·경영지원 등은 꺼져요. 직접 바꿀 수 있어요. 공통 안내에서 "포트폴리오"가 들어간 줄은 켰을 때만 공고에 붙어요.
4. **"✨ 공고문 만들기 (AI 초안 3가지)"**: 서로 다른 방향의 초안 3가지를 한 번에 만들어요. 위에서 **A안 · 직무정의서 중심 / B안 · 기존 공고 문체 / C안 · 간결형**을 눌러 골라보세요. 고른 안이 아래 공고문 칸에 들어가고, 고친 뒤에 다른 안을 누르면 고친 내용이 사라진다고 물어봐요. 초안은 아래를 참고해서 써요.
   - 입력한 팀·포지션·근무 조건과 회사 정보(사명·인재상)
   - **팀 직무 참고**(아래 설명) — 직무정의서에서 옮긴 공개 가능한 내용
   - 같은 팀의 지난 공고와 오픈한 공고 문체 예시 4개(말투·구성 참고용이고, 문장을 그대로 베끼지 않게 했어요)
   - **경력도 AI가 추천해요 — 공고문이 아니라 위 "경력" 칸에 추천값으로 들어가요.** AI는 포지션 상세(공고문)에는 연차를 쓰지 않고, 같은 팀의 지난 공고·지난 공고에서 쓴 경력 조건(앱에 정리해 둠)·팀 직무 참고를 근거로 경력 조건(예: `경력 3년 이상`, `경력무관(신입포함)`)을 추천해요. 추천값이 들어가면 칸 아래에 "추천값이에요 — 맞아요" 안내가 보여요. 맞는지 확인하고 고치거나 **"맞아요"**를 눌러주세요. **사람이 먼저 쓴 경력은 AI 추천값이 덮어쓰지 않아요.** 필요한 역량·우대 사항도 같은 근거로 추천해요.
   - 앱이 모르는 정보는 지어내지 않고 `[입력]`으로 남겨요.
   - 맨 위 **모집 개요**는 입력한 값 그대로 붙고(접수 기간 포함), 맨 끝에 **공통 안내**가 붙어요.
5. **"✅ 공고 확정"** 또는 **"임시 저장"**: 확정한 공고만 "이력서 검토" 탭의 **평가할 공고**에 나와요. 확정할 때 **경력 칸이 비어 있거나 추천값을 아직 확인하지 않았으면** 확인창이 떠요(공고 점검 경고가 있으면 같은 확인창에 합쳐서 알려요). 막지는 않아요. 본문에 `[입력]` 표시가 남아 있으면 한 번 더 물어봐요. 확정된 공고의 경력·학력 조건은 이력서 평가 글 끝에 `[사람인 핵심 정보]`로 덧붙어서, 포지션 상세에 연차가 없어도 평가의 "경력 연차" 항목이 근거로 써요.

**확정한 공고 고치기**: 조회에서 "수정"을 누르면 편집기에 불러와져요. "평가에 사용"을 누르면 이력서 검토 탭으로 넘어가 그 공고가 선택돼요. 고친 뒤 **"수정 내용으로 다시 확정"**하거나 **"작성 중으로 되돌려 저장"**(평가 목록에서 빠짐)할 수 있어요.

**팀이 맡은 브랜드** ("팀과 맡은 브랜드 보기·수정"): 팀별로 맡은 브랜드(예: 인디비주엘, 우일신)를 적어두는 칸이에요. **처음에는 모두 비어 있고**(어느 팀이 어느 브랜드를 맡는지 앱이 알지 못해서 지어 넣지 않았어요), 평소에는 **잠겨 있어요.** "수정"을 눌러 입력하고 "저장"해야 반영돼요. **팀 이름은 바꿀 수 없어요**(팀 목록은 문자 보내기·면접 일정과 같아요). 공고 만들기에서 팀을 고르면 그 팀의 브랜드가 안내로 보이고, **AI 공고 초안이 참고**해요(공고 본문에는 자동으로 적히지 않아요). "이력서 검토·공고" **보기** 권한이면 읽을 수 있고, **수정** 권한이 있을 때만 "수정" 버튼이 보여요.

**JD(공고문 본문) 추천**: AI는 JD 본문만 써요. 맨 위 모집 개요(팀·포지션·근무 조건·접수 기간)와 맨 끝 공고 안내는 AI가 아니라 입력·저장된 값이 붙어요. **포지션 이름(MD, 포토, 디자이너 등)은 담당자가 직접 입력**하고, AI는 그 종류를 판단해 이전에 올려주신 공고(경영지원·디자이너·유통 MD·물류·글로벌 MD·아동화 디자이너·콘텐츠 크리에이터·뷰티 MD·마케팅 팀장) 중 가장 비슷한 포지션의 구성과 문체를 따라 써요. 같은 팀의 지난 공고(앱에 저장된 것)와 팀 직무 참고, 팀이 맡은 브랜드도 함께 참고해요.

**공고 안내(공통 안내)** ("공고 안내(공통 안내) 보기·수정"): 근무 시간 · 급여 안내 · 전형 절차(결과 안내 문장 포함) · 지원 방법 · 복지 · **채용서류 반환·보관 안내**예요. **처음 한 번은 빈칸(`[입력]`)을 채워서 저장해 주세요**: 결과를 알리는 기간, 채용서류 반환 청구 기간(채용 확정일부터 14~180일 사이)·청구 방법·보관 기간은 회사가 정하는 값이라 비워 뒀어요. 한 번 채워 저장하면 이후 만드는 공고에는 빈칸이 없어요. 채우지 않으면 공고 점검이 "아직 채우지 않은 칸"으로 막아 줘요. **이미 공통 안내를 저장해 두셨다면 새 기본 문구는 반영되지 않아요.** 그 경우 공고 점검의 "채용서류 반환·보관·파기 안내가 없어요" 항목의 추천 문구를 쓰거나, "수정"에서 직접 추가하세요('기본 문구로 되돌리기'를 누르면 새 기본 문구가 나오지만 지금 저장해 둔 내용은 사라져요). **평소에는 잠겨 있고**, **"수정"**을 눌러 고친 뒤 **"저장"**(또는 "취소")해야 반영돼요. "기본 문구로 되돌리기"는 수정 중에만 보여요. 처음 문구는 오픈한의 2025년 채용 공고(사람인)에서 읽은 내용이라 **지금과 다를 수 있으니 꼭 확인**하세요(전형 절차는 최근 공고 기준으로 컬처핏 인터뷰를 뺐어요). "기본 문구로 되돌리기"도 있어요.

**팀 직무 참고** ("팀 직무 참고 보기·수정"): 팀을 고르면 그 팀의 내용이 나와요. **AI 공고 초안과 이력서 평가가 함께 참고**해요. 처음 내용은 직무정의서 문서(경영지원팀)와 직무정의서 시트에서 옮겼어요. 업데이트된 직무정의서(엑셀)는 아래 "직무정의서 반영"처럼 온라인팀·그로잉업팀·FC팀에 반영했어요.
- **공개해도 되는 내용만** 적으세요. IPO 일정, 자회사, 내부통제, 인력 계획 같은 **대외비는 처음 내용에도 넣지 않았어요.** 직접 고칠 때도 넣지 마세요(AI 서비스로 전달돼요).
- 직무정의서는 재직자 성장 목표가 섞여 있어서, 이력서 평가에서는 "입사 시점의 완성도를 요구하지 않는다"는 주의와 함께 전달돼요.
- **직무정의서 반영(엑셀 시트 기준)**: **온라인팀**에는 인디비주엘과 비주얼팀(포토그래퍼)을 포함해서 MD 직무능력과 비주얼(포토그래퍼) 직무를 덧붙였어요. **그로잉업팀**은 시트의 "일상화보팀"이고 MD 공통 직무능력표를 넣었어요(예전에는 참고가 없었어요). **브이팀**은 시트의 "우일신팀"이고 MD 공통 직무능력표를 넣었어요. **FC팀**은 시트의 "오프라인 영업팀"이고 예전 참고에 MD 직무능력을 덧붙였어요. 경영지원·SCM·와우서비스·마케팅·제품디자인팀은 **예전 내용 그대로**예요.
  - 옮긴 항목은 **공고에 쓸 수 있는 직무능력과 업무 도구**(매출관리·상품기획력·노출 구좌 확보/협상·마케팅·재고 파악·딜 기획력 등, 구글 스프레드 시트·이지어드민·카페24·노션·파워포인트)뿐이에요. 시트에 있던 **내부 평가·자기계발 항목**(신체·정신·개인 재무·인맥 관리, 서적, 핵심 가치 습관, 멘토 충실도, 연간 KPI 등)과 **내부 통제 및 소통**(조직관리·리스크관리) 구분은 대외비나 지원자에게 요구하면 안 되는 내용이라 **제외**했어요. 사람 이름이 붙은 의견 열(theo·lucy·hans 개선안)은 데이터가 비어 있었어요.
  - 시트의 팀원/팀장 표시가 시트마다 달라서(같은 항목이 한 시트에서는 팀원, 다른 시트에서는 팀장) 직급을 나누지 않고 **표에 적힌 순서대로 "기본 → 심화"**로 옮겼고, 팀원 포지션에는 맨 앞 단계만 참고하라고 적었어요. 비주얼(포토그래퍼)은 순서가 수준을 뜻하지 않아 항목을 나열했어요.
  - **반영하지 않은 시트**: `글로벌팀`(`오프라인 영업팀`과 내용이 글자까지 같은 복사본이라 글로벌비즈니스팀에 붙이면 엉뚱한 설명이 돼요), `꿈비 직무정의서_raw`(다른 회사 자료로 보여요). 온라인팀·우일신팀·인디비주엘팀·일상화보팀 시트도 서로 내용이 같은 복사본(MD 공통 표)이라 온라인팀·그로잉업팀·브이팀에 같은 내용을 넣었어요.
  - 저장해 둔 팀 직무 참고가 있으면(예전에 직접 고쳤다면) 그 값이 우선이라 이 기본값이 보이지 않아요. "팀 직무 참고 보기·수정"에서 **"처음 내용으로 되돌리기"**를 누르면 새 기본값이 나와요.
- 정리된 내용이 없는 팀은 직접 적어두면 돼요. "처음 내용으로 되돌리기"도 있어요.

**공고 조회** (같은 탭 아래쪽): **생성일 기준**으로 보고, 기본은 **최신순**이에요. 팀별·상태별(확정·게시중·마감·작성 중)로 거를 수 있고, 오래된순으로도 볼 수 있어요. 목록의 **"확정"** 필터는 게시중·마감 공고도 포함해요(평가 대상이었던 공고 전부). "보기"로 공고 전문과 근무 조건을 보고, "평가에 사용"으로 바로 평가할 공고로 고를 수 있어요. 근무 조건 칸에는 접수 마감일도 보여요.

**알아두세요**
- 평가는 **확정된 공고로만** 할 수 있어요. 예전 기본 포지션 5개(경영지원팀·제품디자인팀·글로벌팀·브이팀·포토)는 **사용자가 고쳐 둔 내용 그대로 확정된 공고로 옮겨져** 있어요.
- **팀 이름**: 문자 보내기·면접 일정의 이름(글로벌비즈니스팀, 와우서비스팀, FC팀)과 노션·공고·직무정의서의 이름(글로벌팀, 와우팀, 오프라인 영업팀)이 달라서, 이 앱은 **면접 일정의 이름을 그대로 쓰고** 노션 팀 자동 선택과 팀 직무 참고 찾기에서만 서로 연결해요. (제품생산팀은 아직 노션 팀 이름과의 연결 정보가 없어서 이름이 같을 때만 같은 팀으로 봐요. 직무정의서 시트의 이름과 앱의 팀 이름은 이렇게 연결해요: 오프라인 영업팀 = FC팀, 일상화보팀 = 그로잉업팀, 우일신팀 = 브이팀, 온라인팀 = 온라인팀(인디비주엘·비주얼팀 포함). 맞지 않으면 "팀 직무 참고 보기·수정"에서 고치세요.)
- AI 초안에는 나이·성별·외모·출신 지역·학력·학교 제한처럼 차별로 이어질 수 있는 조건을 쓰지 않게 해뒀어요(학력 조건은 넣지 않아요). 그래도 **게시 전에 꼭 직접 확인**하세요.
- 사명·공통 인재상은 이력서 검토 탭의 접이식 상자에서 보고, "수정 → 저장"으로 고쳐요(권한: 보기만 있으면 읽기만 되고 수정 버튼은 안 보여요).
- 권한: 공고 만들기·수정·삭제·확정, 팀 직무 참고 수정은 **이력서 검토·공고 "수정"** 권한이 필요하고, "보기"만 있으면 공고 조회와 팀 직무 참고 읽기만 할 수 있어요.

## 9-7. PDF 이력서 올리기 → 평가 → 노션 등록 → 문자·일정 폼 채우기

이력서 검토 탭의 "이력서 평가"에서 **PDF를 올리면** 아래 순서로 이어져요.

1. **PDF 올리기**: 칸에 끌어다 놓거나 눌러서 고르세요. (4MB 이하, 스캔한 PDF도 AI가 직접 읽어요. "글 붙여넣기"로 바꿔서 쓸 수도 있어요.)
2. **평가**: 평가할 포지션을 고르고 "평가하기" → 100점 평가표, 총평, 인재상 근거가 나와요. 이때 AI가 이력서에서 **이름·연락처·최종 학력·주요 경력**을 함께 읽어요.
3. **자동 채움**: 읽은 이름·연락처가 아래 "노션에 지원자 등록" 칸에 미리 채워져요. **AI가 잘못 읽을 수 있으니 꼭 확인**하세요. (팀명·면접상태 "서류합격"·지원일도 기본값으로 채워져요)
4. **노션에 등록**: 사람이 확인하고 눌러야 등록돼요 (등록 = 서류합격 처리). 등록하면 노션 「진행중 채용」에 카드가 생기고, 이력서에서 읽은 학력·주요경력이 해당 칸에 들어가며(칸이 있을 때만), **올린 PDF가 카드 본문에 파일로 붙고, 서류 체크리스트도 본문에 기록돼요(9-21).**
5. **이어서 채우기**: 등록이 끝나면 **"📨 문자 보내기에 채우기" / "📅 일정 등록에 채우기"** 버튼이 나타나요. 누르면 문자 화면·일정 폼에 방금 등록한 지원자의 이름·연락처·팀이 채워지고, 문자를 보내면 그 노션 카드에 "문자 발송 완료"가 기록돼요.

**알아두세요**
- 이력서의 성별·생년(나이)·학교·전공·총경력·연봉·이메일·주소는 화면에서 보도록 읽어 오지만(9-26) **사진·주민등록번호·혼인·가족관계는 읽어 오지 않도록** AI에게 지시했고, 혹시 주민등록번호 모양이 어느 칸에 섞여 오면 지워요. 다만 **PDF 파일 자체는 AI(Anthropic)로 전송되고 노션에도 그대로 붙으니**, 사내 개인정보 처리 방침과 맞는지 확인해 주세요. 앱 서버에는 PDF를 저장하지 않아요.
- PDF 첨부만 실패하면(노션 일시 오류 등) 카드는 이미 등록돼 있고, 화면에 **"PDF 다시 붙이기"** 버튼이 나와요. (카드가 두 번 만들어지지 않아요)
- **평가한 PDF만** 붙어요. 평가 뒤에 다른 파일을 골라도 엉뚱한 파일이 붙지 않아요.
- 파일 크기는 **4MB 이하**예요 (배포 서버가 약 4.5MB를 넘는 요청을 받지 못해요). 크면 PDF 압축이나 "인쇄 → PDF로 저장"으로 줄여주세요.
- PDF 분석은 글 평가보다 오래 걸려요(수십 초). 중간에 끊기면 알려주세요.
- 권한: PDF 올리기·평가·노션 등록은 **이력서 검토·공고 "수정"** 권한이 필요해요. "보기"만 있는 사람에게는 이 영역이 보이지 않아요.
- 노션의 PDF는 카드 **본문**에 붙어요 (노션 DB에 "이력서" 칸이 없어서요). 표에서 바로 보이는 칸이 필요하면 노션 DB에 파일 칸을 추가한 뒤 알려주세요.

## 9-8. 노션에 있는 이력서로 점수 기준 만들기 (채용·탈락 평균)

노션 「진행중 채용」에 있는 지원자를 이력서 검토로 불러와 채점하고, 점수를 노션에 기록해서 **"채용된 사람은 보통 몇 점대인지"** 기준을 쌓는 기능이에요.

**쓰는 방법**
1. 이력서 검토 → "이력서 평가"에서 **"노션에서 불러오기"**를 고르고 **"📋 노션 지원자 고르기"**를 눌러요. (팀·상태·이름으로 거를 수 있어요. 채용·탈락한 사람도 보여요)
2. 지원자를 고르고 **"평가하기"**를 눌러요. 노션 카드에 붙어 있는 PDF 이력서를 가져와서 지금 평가표로 채점해요. (노션에는 아직 아무것도 쓰지 않아요. 파일이 여러 개면 고르게 해요)
3. 점수를 확인하고 필요하면 고쳐요. 그다음 **"노션 점수 칸에 기록"**을 누르면 노션 카드의 **종합점수 · 평가 요약 · 평가일시 · 추천** 칸에 기록돼요. (면접상태 등 다른 칸은 바꾸지 않아요. 이미 점수가 있으면 덮어쓸지 한 번 더 물어봐요)
4. 기록이 쌓이면 평가 결과 위쪽의 **"📊 노션에 기록된 점수 기준"**에 결과별 평균이 보여요: 채용·입사(채용 + 계약종료&퇴사), 탈락 확정, 진행 중, 면접 불참. 이 포지션의 팀만 따로 보여주기도 하고, **새 이력서를 PDF로 올려 평가할 때도** 같이 보여요. ("채용된 사람 평균보다 +3점" 식으로 비교해줘요)
5. 같은 박스에 **영역별로 채용된 사람과 탈락한 사람의 평균 차이**가 나와요. 차이가 큰 영역이 JD에서 강조할 만한 부분이에요.

**꼭 알아두세요**
- 점수 기준은 **참고용**이에요. 합격선이 아니고, AI가 점수를 매길 때 쓰는 기준도 아니에요. JD도 자동으로 바뀌지 않아요. 보시고 직접 반영하세요.
- 처음엔 노션에 점수가 하나도 없어서 "기록 없음"이 보여요. 채용된 사람·탈락한 사람의 이력서를 몇 명씩 채점해서 기록해야 기준이 생겨요. **채용된 사람이 5명 미만이면 평균이 크게 흔들린다**는 경고가 같이 떠요.
- 과거 채용 결과를 기준으로 삼으면 과거의 편향이 이어질 수 있어요. 점수는 학교·나이가 아니라 평가표(직무 역량) 기준이고, 점수 기준 화면에는 이름·연락처가 나오지 않아요.
- **AI는 PDF만 읽어요.** 노션에 hwp·docx·이미지로 올려 둔 이력서, 외부 링크로만 걸어 둔 이력서는 가져올 수 없어요(어떤 파일이 있는지는 안내해줘요). 4MB를 넘는 PDF도 안 돼요.
- 이력서 PDF는 AI(Anthropic)로 전송돼요. 채용된 사람·퇴사한 사람의 이력서도 포함되니 사내 개인정보 방침을 확인하세요.
- 점수 기준은 15초 동안 기억해 두고 계산해요. 노션에서 직접 점수를 고쳐도 잠시 뒤 반영돼요.
- 권한: 노션 이력서 평가·점수 기록은 **이력서 검토·공고 "수정"** 권한이 필요하고, 점수 기준은 "보기"만 있어도 볼 수 있어요.
- 노션 연동은 `NOTION_TOKEN`에 더해, 연동에 **읽기·수정·추가 권한 3개**가 모두 켜져 있어야 해요.

## 9-9. 면접 관리 — 지원자 목록·상태·일정 (노션 「진행중 채용」과 같은 데이터, 예전 "지원자 관리"를 합쳤어요)

**"면접 관리" 탭**(예전 "지원자 관리" 탭을 합쳤어요)의 위쪽은 노션의 채용 DB를 **그대로 읽고 쓰는 화면**이에요. 줄마다 아래 9-21의 **"면접 질문·답변"** 버튼이 있어서 같은 화면에서 질문 만들기와 답변·점수 전송까지 이어져요. 앱이 따로 복사본을 갖지 않기 때문에 앱과 노션이 **항상 같은 데이터**예요.

**볼 수 있는 것**: 이름·전화번호, 팀·지원직무, 면접상태, 1차·2차 면접 일시, 면접 문자 안내, 종합점수·추천, 노션 페이지 링크. 면접상태(진행 중 / 전체 / 단계별), 팀, 이름으로 거를 수 있고 "더 보기"로 이어서 볼 수 있어요. 지원자의 **나이·직전 연봉은 목록에 가져오지 않아요.**

**바꿀 수 있는 것** (바꾸면 노션에 바로 저장돼요)
- **면접상태(합격 여부·채용 과정)**: 서류합격 → 1차 면접 예정자 → 채용 과제 → 2차 면접 예정 → 채용 / 탈락 후보 → 탈락 확정 / 불참 / 계약종료&퇴사 (노션에 이미 있는 선택지 그대로예요)
- 1차·2차 면접 일시, 면접 문자 안내(면접 확정·문자 발송 완료·미회신 등), 입사일, 면접 안내 관련 메모 ("수정" 버튼). **바꾼 칸만** 노션에 보내서, 건드리지 않은 날짜는 그대로 유지돼요. 일시는 한국 시간으로 저장돼요.
- **탈락 확정**은 확인창을 거쳐야 바뀌고, AI 점수로는 자동으로 바뀌지 않아요. 잘못 눌렀으면 다른 상태로 되돌릴 수 있어요.

**앱과 노션을 같게 유지하는 방법**
- 앱에서 바꾸면 노션에 즉시 저장돼요. 노션에서 바꾼 내용은 **"새로고침"**을 누르거나 다른 화면에 갔다 돌아오면(30초 이상 지났을 때) 앱에도 보여요. (실시간으로 알려주는 기능은 없어요)
- **충돌 방지**: 내가 화면을 열어 둔 사이에 노션에서 그 지원자가 바뀌었다면, 앱에서 저장할 때 **덮어쓰지 않고** "노션에서 방금 바뀌었어요, 새로고침해주세요"라고 알려주고 그 사람 줄을 최신으로 바꿔요. (노션이 알려주는 수정 시각은 분 단위라서, 같은 1분 안에 일어난 동시 수정은 못 잡을 수 있어요.)

**권한**: 이력서 "보기"만 있는 분(예: 대표이사)은 목록을 볼 수 있고, "수정" 권한이 있는 분만 면접상태·면접 일정을 바꿀 수 있어요.

## 9-10. 여러 이력서 한꺼번에 점수 보기 (이력서 검토 탭 아래쪽)

PDF 이력서를 **최대 20개(파일당 4MB 이하)** 올리고 "점수 보기"를 누르면 **점수만 표로** 보여줘요. 먼저 위 "평가할 공고"를 골라야 해요.
- **같은 파일을 두 번 올리면 마지막 파일로 바뀌어요.** 파일 이름이 같으면(대소문자·앞뒤 공백은 무시) 같은 파일로 보고, 나중에 올린 파일이 이전 줄을 대신해요(이전 점수는 지워지고 다시 "점수 보기"를 눌러야 해요). 한 번에 같은 이름을 두 개 올려도 마지막 하나만 남아요. 바뀐 개수는 상태줄에 알려줘요. 20개가 꽉 차 있어도 같은 이름 교체는 돼요. 단 **점수를 보는 중인 줄**과 **이미 노션에 서류 합격으로 기록한 줄**은 바꾸지 않고 이유를 알려줘요(기록 표시가 사라져 같은 사람을 다시 기록하는 일을 막으려고요). 이름만 같고 다른 사람의 파일이면 바뀌어 버리니, 같은 이름의 서로 다른 이력서는 이름을 구분해서 올려주세요.
- **공고별로 지원자 따로 보기**: 줄마다 "점수 보기"를 누를 때 고른 공고가 기록돼요. 공고가 둘 이상(또는 평가 전 줄이 섞여) 있으면 표 위에 **"공고별 보기"** 칩이 나와요: `전체` · `공고 이름 (인원)` · `아직 평가 전`. 칩을 누르면 그 공고의 지원자만 보여요(정렬을 바꿔도 유지돼요). 공고가 하나뿐이면 칩은 숨겨요. 보고 있던 공고의 줄이 모두 없어지면 자동으로 "전체"로 돌아가요. **"선정"과 "노션에 기록하기"는 칩으로 걸러도 선정한 줄 전부에 적용돼요**(다른 공고에서 선정한 사람도 포함되니, 기록 전 확인창의 이름 목록을 꼭 보세요).
- **한 사람의 서류가 여러 개면 한 명으로 묶어서 통합 점수를 매겨요.** 이력서·파일 이력서·포트폴리오·자기소개서를 따로 올리면 점수 표에 서로 다른 지원자처럼 줄이 생기는데, 점수 보기 전에 **줄 앞의 "묶기"를 체크하고 "선택한 줄 한 명으로 묶기"**를 누르면 한 줄이 돼요(한 사람당 **최대 4개, 합계 4MB 이하**). 묶음 줄에서 "점수 보기"를 누르면 AI를 **한 번만** 부르고, 서류를 모두 함께 읽어 **한 사람으로 통합해서** 점수를 한 번 매겨요(서류끼리 내용이 다르거나 한 서류에만 있는 정보는 근거에 어느 서류인지 적게 해요). 파일 이름은 어떤 서류인지 짐작하는 참고로만 쓰고, 파일 안의 글과 이름 속 지시문은 따르지 않아요.
  - **"같은 이름끼리 묶기 제안"**: 파일 이름에 같은 사람 이름(한글 2~4자)이 2개 이상 들어 있으면 묶을 후보로 보여주고, **확인창에서 승인해야** 묶여요(`이력서`·`포트폴리오`·`온라인`처럼 흔한 말은 이름으로 안 봐요). 틀린 묶음은 줄의 **"묶음 풀기"**로 서류마다 줄로 되돌릴 수 있어요. 이름이 다른 사람의 파일이 우연히 같은 조각을 가질 수 있으니 확인창의 파일 이름 목록을 꼭 보세요.
  - 묶을 수 있는 줄은 **점수를 보기 전(대기)이거나 오류가 난 줄**이에요. 점수를 보는 중인 줄, 이미 노션에 기록한 줄, 가져온 결과는 묶을 수 없어요. 같은 이름의 파일이 겹치거나, 5개 이상이거나, 합계가 4MB를 넘으면 안내하고 아무것도 바꾸지 않아요. 점수를 본 뒤에는 묶음을 바꿀 수 없어서, 다르게 묶으려면 "목록 비우기" 후 다시 올려주세요.
  - **묶음 줄 안의 같은 이름 파일을 다시 올리면 그 파일만 바뀌어요**(묶음은 유지, 점수는 지워져요).
  - **노션에 서류 합격으로 기록하면 서류가 모두 카드에 붙어요.** 한 파일이면 예전처럼 `이름_이력서.pdf`로, 묶음이면 `이름_원래 파일 이름`으로 붙여서 어떤 서류인지 노션에서도 보여요. 일부가 안 붙으면 어떤 파일인지 알려줘요.
  - 서류 합계가 4MB를 넘으면(스캔한 포트폴리오 등) 묶을 수 없어요. 서버(Vercel)가 한 번에 받는 크기 한도 때문이에요. 파일을 줄이거나, 포트폴리오는 따로 두고 이력서만 평가하세요.

- 표: 총점 높은 순(또는 올린 순서), 지원자 이름·파일 이름, 총점, 검토 우선순위, 필수 요건 충족 수(예: 1/4), 확인 필요 영역 수. "점수표"를 누르면 영역별 점수·근거·확신도, 필수 요건, 면접에서 확인할 것, 전공·합격자 비교가 펼쳐져요.
- 시작 전에 **"AI를 N번 부르고 비용이 들어요"** 확인을 물어요. 한 번에 2개씩 평가하고, 실패한 이력서는 그 줄만 "다시 평가"하거나 "빼기"할 수 있어요.
- **노션 페이지는 자동으로 만들지 않아요.** 서류 합격시킬 사람은 줄의 **"서류 합격 확정"** 버튼을 직접 눌러요. 이름·연락처·지원 채널(기본 이메일)·면접상태(기본 서류합격)를 확인하고 "서류 합격 확정하기"를 누르면 노션에 지원자 카드가 만들어지고 점수·요약·학력·경력이 들어가며 이력서 PDF도 붙어요. 확정한 줄에는 **"서류 합격 확정됨"** 표시와 함께 **"📨 면접 문자"**·**"📅 일정 등록"**·"노션에서 열기"가 나타나요. 노션에 같은 사람이 있으면 중복 확인을 물어요. 점수가 낮은 사람도 직접 누르면 등록할 수 있고, 추천 칸은 PASS 또는 BORDERLINE이며 REJECT로는 만들어지지 않아요.
- **서류 합격 선정 → 한 번에 기록**: 점수가 나온 줄마다 **"선정"** 체크가 있어요. 점수를 보며 합격시킬 사람을 체크해 두고(정렬을 바꿔도 체크는 유지돼요), 표 위의 **"선정한 N명 노션에 기록하기"**를 누르면 확인창(이름·점수 목록)이 뜨고, 확인하면 한 명씩 차례로 노션에 **"서류합격"** 카드로 기록하고 이력서 PDF도 붙여요. 이름·연락처는 이력서에서 읽은 값을 써요. 연락처는 AI가 못 읽으면 비어 있고, 지원 채널은 노션에 "이메일"이 있으면 그걸 써요.
  - **노션에 같은 사람이 있으면 건너뛰어요**(강제로 새로 만들지 않아요. 새로 만들려면 줄의 "서류 합격 확정"을 쓰세요). **이름을 못 읽은 줄도 건너뛰어요.**
  - 한 명이 실패해도(노션 거절·네트워크 오류) **나머지는 계속**해요. 끝나면 "N명 기록, M명 건너뜀, K명 실패"가 나오고, 줄마다 사유가 적혀요. 실패·건너뛴 줄은 선정이 유지돼요.
  - 이력서 PDF를 못 붙여도 카드는 남고 줄에 안내가 나와요. 기록 중에는 버튼이 잠겨서 두 번 눌러도 중복되지 않아요.
  - 기록하는 건 **서류 합격뿐**이에요. 보류·탈락은 기록하지 않고, 탈락 확정은 노션에서 사람이 직접 해요. 선정 상태는 화면에만 있어서 닫으면 사라져요(기록한 사람은 노션에 남아요).
- **평가 결과는 저장되지 않아요.** 화면을 닫으면 점수만 본 사람의 결과는 사라지고, 노션에 등록한 사람만 남아요. 표를 비울 때 노션에 등록하지 않은 사람이 있으면 한 번 더 물어요.
- 권한: "이력서 검토·공고" **수정** 권한이 있는 분에게만 보여요(AI 비용·노션 등록 때문이에요).

## 9-11. 이전 서류 합격자 참고 + 종합 코멘트

이력서를 평가할 때(이력서 평가·PDF·노션 평가·여러 이력서 점수 모두) **"노션의 이전 서류 합격자를 참고해서 평가"** 체크칸이 기본으로 켜져 있어요.

- **어떻게 참고하나요**: 모델을 따로 학습시키는 게 아니라, 평가할 때마다 노션 「진행중 채용」에서 **같은 팀의 서류 합격 기록**(최근 순으로 최대 50명을 읽어 15명까지)을 AI에게 참고 자료로 함께 보여줘요. 공고의 팀 이름은 노션의 팀 이름으로 연결돼요(글로벌비즈니스팀=글로벌팀, 와우서비스팀=와우팀, 경영지원팀=경영지원팀·경영지원팀장). 읽은 결과는 10분 동안 기억해요.
- **AI에게 보내는 것**: 합격자의 **지원직무·전공·주요경력**뿐이에요. 학력 칸에서는 "서울대학교 시각디자인학과"에서 **"시각디자인학과"만** 뽑아서 보내요. **이름·연락처·나이·희망/직전 연봉·학교 이름·종합점수·추천·면접상태는 보내지 않아요.** 경력 글 속 HTML과 줄바꿈은 정리해요.
- **결과 화면**: "전공 · 이전 서류 합격자와 비교" 상자에 전공 관련성(직무 관련·일부 관련·관련 낮음·확인불가), 이전 합격자와의 유사도(높음·보통·낮음·참고 불가), 비슷한 점·다른 점, 점수에 참고한 방식, 참고한 합격자 수와 전공 분포가 나와요. **서류 총평은 이력서 종합 코멘트**(경력·전공·성과 요약 → 합격자와 비슷한 점·다른 점 → 면접 확인점)예요.
- **점수에는 어떻게 반영되나요**: AI에게 합격자 참고를 유사 경력·공고문 적합도 점수의 **소폭 보정으로만** 쓰고, 닮았다는 이유만으로 가점하거나 다르다는 이유만으로 감점하지 말고, 근거는 이력서의 직무 관련 경험으로 하라고 지시해요. 같은 팀 합격자가 **5명 미만이면** "참고로만 쓰라"는 경고를 함께 보내요. 다만 AI가 실제로 얼마나 지켰는지는 확인할 수 없어요. 화면의 "점수 반영" 줄은 AI가 스스로 설명한 문장이에요.
- **쓰지 않는 기준**: 학교 이름·학교 수준·나이·성별·거주지로는 합격자와 비교하지 않아요. 전공은 "직무에 필요한 전공인가"와 "합격자들의 전공과 겹치는가"만 봐요. 학력 점수는 앞서 정한 대로 총점에는 들어가지만 검토 우선순위(적극 추천·추천·보류)에는 영향이 없어요.
- **노션이 안 될 때**: 평가는 그대로 진행돼요. 결과에 "노션에서 합격 기록을 읽지 못해 참고하지 않았어요", "노션에 같은 팀의 참고할 합격 기록이 없어요", "합격자 참고를 끈 평가예요" 중 알맞은 안내가 나와요. 노션 연동이 꺼진 서버에서는 합격자 참고가 자동으로 꺼져요.
- **주의**: 과거에 합격시킨 사람들을 기준으로 삼으면 **과거의 선호가 되풀이될 수 있어요.** 합격자와 닮은 지원자가 더 좋은 지원자라는 뜻이 아니니, 참고 정보로만 보세요. 노션의 학력·주요경력 칸이 비어 있으면 참고할 내용이 줄어요. 이 기능은 합격자 정보를 AI 서비스(Anthropic)로 보내므로, 쓰기 전에 사내 개인정보 처리 방침과 맞는지 확인해주세요(원치 않으면 체크를 끄면 돼요).

## 9-12. 서류 합격 확정 → 면접 문자 → 면접 확정 (인사 담당이 진행)

면접은 대표이사님이 직접 보는 게 아니라, **인사 담당이 서류 합격자의 면접 스케줄을 확인해 문자를 보내고 확정**하는 흐름이에요. 앱은 이 순서대로 이어서 쓸 수 있게 해줘요.

1. **서류 합격 확정**: 이력서 평가(또는 "여러 이력서 점수 보기")에서 점수를 확인한 뒤 **"서류 합격 확정"**을 눌러요. 노션에 면접상태 "서류합격"으로 지원자 카드가 만들어져요.
2. **면접 일정 확인·문자 보내기**: 확정한 직후 나오는 **"📨 면접 문자"**(또는 "면접 관리" 목록 줄의 **"📨 면접 문자"**)를 누르면 문자 보내기 화면이 열리고 이름·연락처가 채워져요. "📅 일정 등록(일정)"으로 면접 일정 화면을 채울 수도 있어요. 문자를 보내면 노션의 **면접 문자 안내가 "문자 발송 완료"**로, 면접연락 시각이 자동 기록돼요.
3. **면접 확정**: 지원자와 시간이 정해지면 "면접 관리"에서 줄의 **"수정"** → 면접 일시를 입력하고 **"✅ 1차 면접 확정"**(또는 2차)을 눌러요. 확인창이 일시를 한 번 더 보여주고, 확정하면 노션에 **면접상태("1차 면접 예정자" 또는 "2차 면접 예정"), 면접일, 면접 문자 안내("면접 확정")**가 한꺼번에 저장돼요.
- "📨 면접 문자"·"📅 일정" 버튼은 서류합격·1차 면접 예정자·채용 과제·2차 면접 예정 단계의 지원자에게만 보이고, 문자·일정 **수정 권한**이 있는 분에게만 보여요. 면접 확정 버튼은 이력서 "수정" 권한이 필요해요.
- **문자 보내기의 면접 일정과 맞는지 자동으로 비교해서 보여줘요.** 같은 사람의 면접 일정이 노션(1차·2차 면접일)과 문자 보내기의 "면접 일정" 두 곳에 따로 있어서, 면접 관리의 1차·2차 면접 칸 아래에 일정과 맞는지 배지로 알려줘요.
  - **짝 찾기**: **연락처(숫자만 비교, 하이픈 무시)**가 같으면 같은 사람으로 봐요. 연락처가 일치하는 일정이 없으면 **이름 + 팀**(노션의 글로벌팀=글로벌비즈니스팀 같은 별칭 포함)이 같은 일정을 쓰고, 이때는 배지에 **"(연락처 다름)"** 경고가 붙어요. **이름만 같은 일정은 짝짓지 않아요**(동명이인일 수 있어요). 연락처가 달라 짝짓지 못한 같은 이름의 일정은 이름 칸에 **"연락처가 다른 일정 N건"**으로 알려줘요.
  - **비교 결과**: ✓ 일정과 일치 / ⚠ 일정과 달라요(일정 시각을 같이 보여줘요) / 일정에 없어요(노션에만 있음) / 노션에 없어요(일정에만 있음) / 날짜만 일치(노션엔 날짜만 있고 같은 날 일정이 있음). 노션의 시각은 한국 시간으로 바꿔 분 단위로 비교해요(UTC 등으로 저장돼 있어도 같은 시각이면 일치). **취소된 일정은 비교에서 빼요.** 같은 사람·같은 구분의 일정이 여러 개면 가장 최근에 등록한 것을 써요. **채용과제 일정은** 노션의 1·2차 면접일 칸과 대응이 없어 비교하지 않아요.
  - **맞추기**: 서로 다를 때 **어느 쪽으로 맞출지는 사람이 버튼으로 골라요.** 자동으로 덮어쓰지 않고, 양쪽 값을 보여주는 확인창을 거쳐요. **"노션 → 일정"**(일정 수정 권한 필요)은 일정의 시각을 노션에 맞추고 일정의 **변경 이력**에 "면접 관리에서 노션 일시에 맞춤"이 남아요. **"일정 → 노션"**(이력서 수정 권한 필요)은 노션의 면접일을 일정에 맞춰요. 노션에 날짜만 있고 시간이 없으면 "노션 → 일정"은 시간을 줄 수 없어서 확인창 전에 막고 안내해요. 연락처가 달라 이름+팀으로만 짝지은 경우에는 확인창에 "같은 사람이 맞는지 확인하세요" 경고가 함께 나와요.
  - **저장 뒤에도 따라 바뀌어요**: 상태 변경·1차(2차) 면접 확정·수정·맞추기로 노션을 저장하면 그 줄의 일정 비교를 다시 계산해요.
  - **권한**: 일정에는 이름·연락처·장소가 있어서 **"면접 일정 보기" 권한이 있는 분에게만** 배지와 비교 결과가 보여요(이력서 권한만 있으면 안 보여요). 맞추기 버튼은 위의 수정 권한이 있을 때만 보여요.
- 앱은 **면접 시간이 겹치는지(다른 사람과 같은 시간인지)는 자동으로 확인해주지 않아요.** 그건 면접 일정 화면에서 직접 확인해주세요. 면접 확정은 노션에만 저장되고, 앱의 면접 일정 화면에는 자동으로 등록되지 않아요. 등록하지 않으면 위 배지가 "일정에 없어요"로 보이고, "📅 일정"으로 채워서 등록하면 "일치"가 돼요.
- 면접 일시는 모두 **한국 시간**으로 입력·저장돼요. 브라우저의 시간대가 달라도 같은 시각으로 보이도록 시험했어요.

## 9-13. 데이터가 안 보이거나 화면이 이상할 때 (원인 구분하기)

**먼저 알아둘 것: 화면에서 "사라진 것처럼" 보여도 저장된 데이터는 대부분 그대로예요.** 저장된 데이터와 화면은 따로라서, 아래 세 가지 중 하나가 원인인 경우가 많아요.

1. **Redis(Upstash) 연결이 빠졌을 때 — 가장 흔해요.** 앱은 Vercel 환경변수 `UPSTASH_REDIS_REST_URL`과 `UPSTASH_REDIS_REST_TOKEN`(또는 `KV_REST_API_URL`·`KV_REST_API_TOKEN`) **두 개가 모두** 있어야 Redis에 저장해요. 하나라도 없으면 **조용히 이 서버의 임시 파일**에 저장하고, 그 파일은 비어 있으며 재배포하면 사라져요. 이때 Redis에 있던 데이터는 **지워진 게 아니라 연결이 빠진 것**이에요. Redis 조회가 실패(응답 없음 등)해도 앱은 오류 없이 **빈 목록**을 보여줘요.
2. **파일을 일부만 새 버전으로 올렸을 때.** `server.js`와 `public` 폴더(`index.html`·`app.js`·`style.css`)는 **항상 한꺼번에 같은 버전**으로 올려야 해요. 일부만 올리면 `app.js`가 중간에 멈추면서 발송 이력·면접 일정·양식이 비어 보이고 지원자 관리 같은 탭이 동작하지 않을 수 있어요. 이 경우 화면 맨 위에 **빨간 경고 띠**("서버와 화면 파일의 버전이 달라요" 또는 "화면 프로그램(app.js)이 중간에 멈췄어요")가 떠요. 경고에는 "데이터는 지워진 게 아니에요"라고 함께 적혀 있어요.
3. **브라우저가 옛날 파일을 보여줄 때.** 새로고침을 **Ctrl+Shift+R**(맥은 Cmd+Shift+R)로 해보세요.

**저장소 상태 확인하는 법 (로그인한 상태에서)**: 브라우저 주소창에 `내 사이트 주소/api/storage-check`를 입력해서 열어요. (구글 로그인을 쓰는 경우 소유주만 볼 수 있어요.)
- `storageMode`가 **`upstash-redis`**면 Redis에 연결된 거예요. **`local-file`**이면 Redis를 안 쓰는 중이에요(→ `warning`에 이유와 해결 방법이 한국어로 나와요: 토큰이 없음, 주소가 없음, 둘 다 없음, 연결 도구를 못 불러옴).
- `dataCounts`에 **문자 발송 이력·면접 일정·문자 양식·공고·사명 인재상·공고 기본값·팀 직무 참고·팀이 맡은 브랜드**가 각각 **저장돼 있는지(`saved`)와 몇 건(`count`)**인지 나와요. `saved: false`는 "저장된 적 없음", **`error`가 있으면 Redis에서 읽지 못한 것**이에요(지워진 게 아니에요).
- `redisRoundTrip.ok`가 `false`면 Redis에 접속은 되는데 읽기·쓰기가 안 되는 거예요.

**Redis에 데이터가 정말 있는지 직접 보려면**: Upstash 콘솔(console.upstash.com) → 해당 Redis → **Data Browser**에서 `history`, `schedules`, `templates`, `postings` 같은 키를 찾아보세요. 키가 보이면 데이터는 안전하게 남아 있는 거예요. **이때 Redis의 키를 지우거나 "Flush"를 누르지 마세요.**

**버전 번호**: `server.js`의 `APP_VERSION`, `public/app.js`의 `APP_VERSION`, `public/index.html`의 `<html data-app-version="…">`는 **세 곳이 같은 값**이어야 해요. 이 값을 바꿀 때는 세 곳을 함께 바꾸세요(다르면 위의 경고 띠가 떠요).

## 9-14. 공고 점검 (공고 만들기 화면, 공고문 칸 바로 아래)

공고문을 쓰다 잠깐 멈추면 **자동으로 점검**해서, 놓치기 쉬운 표현을 알려줘요. **규칙 기반이라 AI 비용이 들지 않고**, 같은 글이면 항상 같은 결과가 나와요. **법률 자문이 아니고, 판단은 담당자가 해요.**

- **수정 필요**: 직무와 무관한 개인정보를 요구하는 표현(사진 첨부, 주민등록번호, 가족·혼인·재산·신체 정보 등), 아직 채우지 않은 `[입력]` 칸
- **확인 필요**: 나이·세대("MZ", "디지털 원어민")·성별·외모·혼인/출산·출신 지역·학벌·종교/장애를 제한하거나 암시하는 표현, 과장·허위로 읽힐 표현("고수익 보장" 등), 남아 있는 `[추천]` 표시(예전 공고), **빠진 안내**(근무지·고용 형태·급여·전형 절차·지원 방법), 접수 마감일이 이미 지난 경우, 내용이 너무 짧은 경우
- **참고**: 학력 제한 표현, 급여를 "면접 후 협상"으로만 적은 경우(2026년 10월 기준 채용공고에 임금 범위를 적게 하는 법안이 국회에서 논의 중이고 노동부도 검토 중이라 **아직 법 의무는 아니에요**), 전형 결과를 언제·어떻게 알리는지 없는 경우, 접수 기간(마감일) 표기가 없는 경우
- **채용절차법 관련 점검 (2026년 10월 기준, 참고용)**
  - **채용서류 반환·보관·파기 안내가 없으면 "확인 필요"**로 알려요. 상시 근로자 30명 이상 사업장은 채용 여부가 확정되기 전까지 채용서류의 반환 청구 기간·방법과 보관·파기 방식을 구직자에게 알려야 해요(채용절차법 제11조). 반환 청구 기간은 채용 확정일부터 14일 이상 180일 이하에서 회사가 정하고, 청구를 받으면 14일 이내에 돌려줘야 해요. 이메일·채용 사이트로 낸 전자 서류는 반환 대상이 아니지만 반환 대상과 절차는 미리 알려야 해요.
  - 이 항목에는 **"추천 문구 공고문에 추가"**와 **"복사"** 버튼이 있어요. 추가하면 공고문 끝에 `[채용서류 반환·보관 안내]`가 붙고, 반환 청구 기간·청구 방법·보관 기간은 `[입력]` 빈칸으로 남아요. **빈칸을 채우지 않으면 "아직 채우지 않은 칸"(수정 필요)으로 잡혀서** 그대로 확정되지 않게 막아요. 이미 같은 안내가 공고문에 있으면 또 붙이지 않아요.
  - **과장·단정 표현**("업계 최고 연봉", "무조건 합격", "인센티브 무제한", "100% 보장" 등 약속하는 말)은 허위·과장 채용광고(제4조) 우려로 "확인 필요"예요. "최고의 팀"처럼 약속이 아닌 말은 걸리지 않아요.
  - **전형 결과 통보**(제8조·제10조 관련)와 **접수 기간**이 없으면 "참고"예요.
  - **주의**: 이 기준은 뉴스·법률 해설·시행령 조문을 보고 정리한 것이고 **법령 정본을 직접 확인한 건 아니에요.** 상시 근로자 30명 미만이면 적용되지 않는 조항이 있고, 임금 공개 의무화 등 법안은 바뀔 수 있어요. 법률 자문이 아니니 **노무사·고용노동부 확인을 권해요.** 새 기준이 나오면 알려주세요.
- "남녀 불문", "나이 무관", "학벌 차별 없이" 같은 **차별 금지 문구는 경고하지 않아요.** 단 "무관 아님"처럼 부정이 붙으면 오히려 반대 뜻이라 경고해요.
- 같은 종류의 표현은 **한 줄로 묶여** 나오고, 항목의 **"위치로 이동"**을 누르면 공고문 칸에서 그 표현이 선택돼요.
- **공고 확정**을 누를 때 확인 필요·수정 필요가 남아 있으면 확인창이 한 번 떠요. **막지는 않아요**(최종 결정은 사람이 해요). `[입력]` 표시가 남아 있으면 점검 결과와는 별도로 "아직 표시가 남아 있어요" 확인창이 한 번 더 떠서, **확인창이 두 번까지** 뜰 수 있어요(같은 `[입력]`을 두 번 묻지는 않아요). 경력 칸 확인은 점검 확인창에 합쳐서 알려요. 어느 확인창이든 "그래도 확정"을 고르면 확정돼요(막지는 않아요).
- **알려진 한계**: 규칙으로 찾는 방식이라 놓치거나 과하게 잡는 표현이 있을 수 있어요. 공고 만들기 화면의 공고문 칸에서 점검해요(저장된 예전 공고도 열면 점검해요).

## 9-15. 문자 발송 직전 확인 (채워지지 않은 칸이 지원자에게 그대로 나가지 않게)

문자를 보내기 직전에 서버가 **채워지지 않은 칸이 남았는지** 확인해요.

- **막아요(보낼 수 없어요)**: 치환되지 않은 `{{…}}`, `[입력]`
- **확인을 물어요("그래도 보낼까요?")**: `【…】`가 남은 경우, **날짜가 들어가는 양식인데 날짜가 비어** 있는 경우(문장이 "결과는 까지 안내드립니다"처럼 깨져 나갈 수 있어요). 사람이 확인하고 보내면 발송돼요. 취소하면 아무것도 보내지 않고 입력한 내용도 그대로 남아요.
- **직접 고친 문구는 날짜를 따지지 않아요.** 미리보기를 직접 고쳐서 양식과 달라졌다면 날짜가 필요 없다고 봐요. 단 양식을 그대로 두고 깨진 문장 뒤에 한 줄만 덧붙인 경우는 "직접 고친 것"으로 보여서 빈 날짜를 못 잡을 수 있어요(**알려진 한계**). 보내기 전에 미리보기를 꼭 읽어주세요.
- 확인창에서 "확인"을 눌러도 **문자는 정확히 1건만 발송돼요**(이중 발송 방지를 시험으로 확인했어요).
- 막힌 문자와 확인 대기 중인 문자는 **발송 이력에 남지 않아요.**
- 기존 기본 양식 17종은 날짜를 채우면 이 확인에 걸리지 않아요.

## 9-16. 브랜드 선택 (팀 옆의 "브랜드 없음(공통) / 있음")

공고 만들기에서 **팀 옆의 "브랜드"**를 고를 수 있어요. 포지션이 꼭 브랜드와 관련 있는 것은 아니라서, 평소에는 **"없음 (공통)"**이고 보이지 않아도 돼요.

- **없음 (공통)**: 특정 브랜드가 없는 공고로 봐요. 팀에 브랜드가 여러 개 등록돼 있어도 AI에게 브랜드 정보를 보내지 않아요.
- **있음**: 그 팀이 맡은 브랜드(공고 기본 정보의 "팀과 맡은 브랜드"에 적어 둔 것) 중에서 고르는 칸이 나타나요. 고른 브랜드만 AI 초안에 전달되고, **AI가 맨 위 소개 문장에 "그로잉업팀 아기동백 소속으로 …"처럼 팀 이름 다음에 브랜드 이름을 써요.** JD 템플릿으로 채워도 소개 문장의 `{{brand}}` 자리에 들어가요(`{{team}}{{brand}} 소속으로`). 모집 개요에는 브랜드 줄을 따로 넣지 않아요. 팀에 등록된 브랜드가 없으면 "있음"은 고를 수 없어요.
- 팀을 바꾸면 브랜드는 "없음 (공통)"으로 돌아가요(이전 팀의 브랜드가 따라가지 않아요). 저장한 공고를 열면 그 브랜드가 그대로 나와요. 나중에 팀 브랜드 표에서 그 브랜드를 지워도 **이미 저장된 공고는 그대로 유지**돼요.
- 같은 팀·같은 포지션이라도 브랜드가 다르면 **별개의 공고**예요. 공고 조회에는 브랜드 이름표가 붙고, 이력서 평가의 공고 목록과 평가 결과에는 `[브랜드]`가 붙어 구분돼요.
- 노션의 "지원직무" 칸에는 브랜드가 섞이지 않아요. (공고 이름 속 `[…]`는 그 공고의 실제 브랜드와 **정확히 같을 때만** 떼요. 옛 공고의 "크리에이터 [비바라비다]"처럼 이름의 일부인 대괄호는 건드리지 않아요.) 노션에 브랜드를 따로 기록하지는 않아요.
- **포지션 입력 추천**은 같은 팀에서 만든 포지션을 먼저, 이어서 다른 팀에서 쓴 포지션이 나와요(디자이너·MD·회계처럼 여러 팀에서 반복되는 이름을 쉽게 고르도록). "이미 만든 포지션이에요"는 같은 팀·같은 포지션·같은 브랜드일 때만 나와요.

- **브랜드 바로 추가·삭제**: 공고 만들기의 브랜드 줄 아래 "이 팀의 브랜드 추가·삭제" 칸에서 팀의 브랜드를 칩(이름 + ✕)으로 보고, 이름을 쓰고 **"＋ 추가"**(또는 Enter)로 추가하거나 ✕로 지울 수 있어요. 아래 "팀과 맡은 브랜드 보기·수정"과 같은 데이터를 바로 저장하고, 추가하면 그 브랜드가 **바로 선택**돼요(브랜드가 하나도 없던 팀도 여기서 첫 브랜드를 추가할 수 있어요). 쉼표(,)·슬래시(/)가 든 이름, 이미 있는 이름, 한 팀 합계 100자를 넘는 경우는 이유를 알려주고 막아요. ✕는 확인창을 띄우고, **이미 만든 공고에 적힌 브랜드는 지워도 그대로**예요(그 공고를 열면 "현재 목록에 없음"으로 보여요). 아래 패널을 수정하는 중에는 입력한 글이 사라지지 않도록 이 칸을 막아요. "보기" 권한만 있으면 공고 만들기 자체가 보이지 않아요.

## 9-17. JD 템플릿 (AI 없이, 비용 없이 공고 본문 채우기)

포지션 이름에 맞는 **JD 템플릿**을 추천해서 공고 본문을 채워 줘요. **AI를 부르지 않아서 비용이 들지 않아요.** 공고 만들기의 공고문 칸 바로 위 "JD 템플릿" 박스에서 써요.

- **기본 8종**: 마케팅(브랜드/퍼포먼스), 온라인(이커머스/온라인 MD), FC(오프라인 매장 관리), 글로벌 비즈니스(해외 영업), 제품 디자인(의류 디자이너), 인사/총무, 재무/회계, 경영지원 총괄 팀장. 올려주신 "패션 브랜드 AI 이력서 검수 가이드 및 직무별 JD" 문서의 JD를 링크 공고 형식(소개 문장 + 소제목 3개)으로 옮겼어요. **옮기면서 바로잡은 부분**: "FC (Field Field Supervisor" 중복, "수주회 참과"(→참가), "ERP, ERP-패션" 중복, "온보딩 program"(→프로그램), 사방넷·플레이오토·카페24를 "패션 전용 ERP"로 묶은 표현(→쇼핑몰 통합관리 솔루션·쇼핑몰 플랫폼), 확인하지 못한 이름("세라픽스", "CPAT")은 뺐어요. **채우기 전에 우리 회사 사정에 맞는지 꼭 읽어보세요.**
- **추천**: **팀을 고르면** 그 팀의 템플릿 버튼이 바로 나와요("경영지원팀 템플릿:"). 인사/총무·재무/회계·경영지원 총괄 팀장은 모두 경영지원팀 안의 포지션이라, 경영지원팀을 고르면 세 개가 모두 보여요(포지션을 아직 안 썼으니 어느 하나를 강조하지 않아요). **포지션을 쓰면** 이름에 어울리는 단어가 있는 템플릿이 맨 앞에 오고 그것만 강조돼요("추천:"). 예: "회계 담당"→재무/회계, "인사총무"→인사/총무, "팀장"→경영지원 총괄 팀장, "콘텐츠 크리에이터"→마케팅. 단어가 안 맞는 포지션이어도 그 팀의 템플릿은 계속 보이고, **다른 팀의 템플릿은 단어가 맞을 때만** 나와요. 템플릿이 없는 팀에서 포지션도 안 썼으면 추천 줄이 보이지 않고, 아래 선택칸에서 직접 골라 채울 수 있어요. 추천은 최대 5개까지예요.
- **포지션을 비워 둔 채 누르면**: 템플릿 이름으로 포지션 칸을 채워서 진행해요(예: "재무/회계", "마케팅 (브랜드 / 퍼포먼스)"는 괄호 설명을 뗀 "마케팅"). 채웠다는 안내가 나오니 필요하면 고치세요. **이미 쓴 포지션은 절대 바꾸지 않고**, 쓰던 공고문이 있어서 덮어쓰기 확인에서 취소하면 포지션 칸도 그대로예요.
- **채우기**: 모집 개요 + 템플릿 본문 + 공고 안내(공통 안내)가 한 번에 들어가요. 이미 써 둔 공고문이 있으면 "쓰던 내용은 사라져요" 확인을 먼저 물어요. **채운 뒤에는 공고문 칸에서 마음대로 고칠 수 있어요.**
- **경력은 추천값이에요**: 템플릿마다 경력 추천값(예: `경력 3년 이상`)이 있고, 채울 때 위 "경력" 칸에 추천값으로 들어가요. 본문에는 연차 숫자를 쓰지 않았어요(연차를 칸 하나로만 관리해야 공고마다 연차가 어긋나지 않아요). 템플릿 수정에서 경력 추천값도 고칠 수 있어요. 소개 문장의 `{{team}}{{brand}}`는 채울 때 팀 이름과 브랜드로 바뀌어요("그로잉업팀 아기동백 소속으로", 브랜드가 없으면 "그로잉업팀 소속으로"). 예전 순서(`{{brand}}{{team}}`)로 직접 저장해 둔 템플릿은 그대로 "브랜드 팀" 순서로 채워져요. 채운 공고는 공고 점검에서 차별·개인정보·빠진 안내 경고가 나오지 않는 것을 확인했어요.
- **템플릿 고치기**: 공고 만들기 아래쪽 "JD 템플릿 보기·수정"에서 **평소에는 잠겨 있고 "수정 → 저장/취소"**로 이름·추천에 쓸 단어·본문을 고쳐요. 기본 템플릿을 고치면 "(수정됨)"이 붙고 **"기본값으로 되돌리기"**로 처음 내용으로 돌아가요. **"＋ 새 템플릿 추가"**로 포토그래퍼 같은 새 템플릿을 만들 수 있고(최대 40개), 직접 추가한 것만 삭제할 수 있어요. 기본 템플릿은 삭제할 수 없어요.
- **본문 형식**: 맨 위에 포지션 소개 문장(없어도 돼요)을 쓰고, 그 아래 소제목 3개(`이런 일을 함께해요` · `이런 분이었으면 좋겠어요` · `이런 경험이 있다면 더 좋아요`)를 **대괄호 없이** 이름·순서 그대로 한 줄씩 지켜야 해요. "이런 분이었으면 좋겠어요" 아래에는 항목이 한 줄 이상 있어야 해요. 소개 문장 등에는 `{{team}}`(팀 이름)과 `{{brand}}`(고른 브랜드)만 쓸 수 있고, 다른 `{{…}}`는 공고에 그대로 나가므로 저장할 때 거절해요. 끝에 "○○팀에서 얻을 수 있는 성장 경험" 구역이나 맺음 문장을 덧붙여도 돼요. 어기면 저장할 때 한국어로 안내하고 저장하지 않아요.
- 권한: "이력서 검토·공고" **보기**는 템플릿을 읽을 수 있고, **수정**이 있어야 고치기·추가·삭제·채우기를 할 수 있어요.

## 9-18. 패션 직무형 평가표 (공고의 채용 유형에서 선택)

공고 만들기의 **채용 유형**에서 "경력직 / 신입직 / **패션 직무형**" 중에서 고를 수 있어요. 패션 직무형은 올려주신 "패션 브랜드 AI 이력서 검수 가이드"의 기준을 앱의 평가표 형식(S/A/B/C 기준)으로 옮긴 **5항목 100점** 평가표예요.

| 영역 | 배점 | 보는 것 |
|---|---|---|
| 직무 적합성 | 30 | 필수 요건·유사 직무·핵심 툴·카테고리 경험 |
| 정량적 성과 | 25 | ROAS·매출·효율·원가 같은 수치로 확인되는 성과 |
| 카테고리·도메인 이해 | 20 | 패션·유통 이해와 해당 고객층·가격대 경험 |
| 경력의 일관성·성장 | 15 | 경력 흐름과 직급·담당 영역의 성장 |
| 조직 적합성·표현력 | 10 | 자기소개 논리성·협업 경험 |

- **학력 항목이 없어요.** 그래서 추천(검토 우선순위)은 전체 점수로 계산해요(75% 이상 적극 추천, 55% 이상 추천, 그 미만 보류). 학교 이름·명성·학점은 어떤 영역에도 반영하지 않도록 AI에게 안내해요.
- **문서와 다르게 바꾼 점 (확인해 주세요)**: ① 문서의 "타겟층(MZ·3040)과의 유효성"은 지원자 나이를 암시할 수 있어서 **"해당 고객층·가격대의 상품·마케팅 경험"**으로 바꿨어요(지원자의 나이·세대는 보지 않아요). ② 문서의 "잦은 이직 감점"은 **근속이 짧다는 이유만으로 점수를 깎지 않게** 했어요. 계약 기간 만료·프로젝트 종료 같은 사유는 반영하고, 사유를 모르면 점수는 그대로 두고 "면접에서 확인"으로 알려요. ③ "합격/불합격" 판정은 넣지 않았어요(AI는 적극 추천·추천·보류만 내요).
- 평가표 보기("회사 소개 · 공통 인재상 · 평가표 보기")에서 세 평가표를 모두 볼 수 있어요. 
- **함께 고친 기존 오류**: AI에게 가는 평가 안내에 "학력·전공(edu)은 5점 이내"가 모든 평가표에 똑같이 들어 있었는데(경력직은 10점, 신입직은 20점이 맞아요), 이제 평가표의 실제 배점을 써요. 평가표에 학력 항목이 없으면 그 줄 대신 "학력 항목이 없어요"라는 안내가 가요.

## 9-19. API 없이 이력서 평가하기 (AI 키·비용 없이)

이력서 검토의 평가 방식에서 **"직접 채점 (AI 없이)"**와 **"Claude 채팅에 붙여넣기 (API 없이)"**를 고를 수 있어요. 두 방법 모두 **서버에 `ANTHROPIC_API_KEY`가 없어도 동작해요.** (AI 키가 없을 때 안 되는 건 "AI로 평가하기"와 "공고 AI 초안"뿐이에요. 공고 점검·JD 템플릿·문자·일정·노션 관리는 AI 키와 상관없어요.)

**① 직접 채점 (AI 없이)**: 평가할 공고를 고르면 그 공고의 평가표대로 점수 칸이 나와요(경력직 6칸·신입직 4칸·패션 5칸). 영역마다 점수(0~배점)를 넣고, 필요하면 근거 한 줄을 써요. S/A/B/C 버튼으로 기준 점수를 빠르게 넣을 수 있고 "평가 기준 보기"로 기준을 읽을 수 있어요. 모든 영역을 채우고 "점수 계산하기"를 누르면 서버가 합계와 검토 우선순위를 계산해서 **AI 평가와 같은 결과 화면**에 보여주고, **노션 등록도 같은 방법**으로 해요. 배점을 넘는 점수는 조용히 바꾸지 않고 안내해요. 총점·추천은 항상 서버가 계산해요.

**② Claude 채팅에 붙여넣기 (API 없이)**
1. 공고를 고르고 "Claude 채팅에 붙여넣기"를 선택해요. 이력서가 글이면 칸에 붙여넣고, PDF면 비워 두세요.
2. "① 평가 요청문 복사"를 누르면 AI 평가와 같은 기준(회사 소개·인재상·공고문·평가표·규칙)이 든 요청문이 클립보드에 복사돼요. 복사가 막힌 환경에서는 글칸에 보여주니 직접 복사하세요.
3. Claude 채팅(claude.ai)에 붙여넣어 보내요. **PDF는 그 채팅에 직접 첨부**하세요.
4. Claude의 답변을 앱의 "③ 답변 붙여넣기" 칸에 붙여넣고 "점수 가져오기"를 눌러요. 설명 글이 섞여 있어도 JSON을 찾아요. 점수는 평가표 배점으로 정리되고, 추천은 서버가 점수로 다시 정해요. JSON을 못 찾으면 "JSON만 다시 보내줘"라고 요청하라는 안내가 나와요. 다른 공고의 요청문으로 받은 답변이면(평가표가 달라서) 빠진 영역을 알려줘요.
- 비용은 들지 않고 쓰는 Claude 요금제의 사용량을 써요. 사람이 건마다 두 번 붙여넣어야 해서 여러 건엔 번거로워요.
- 이력서에는 개인정보가 있어요. 쓰는 Claude 계정의 개인정보·학습 설정을 확인하세요. 이 앱은 붙여넣은 내용을 저장하지 않아요.
- **알려진 한계**: 직접 채점은 필수 요건 체크표·서류 체크리스트 없이 점수·총평만 받아요. 붙여넣기는 Claude 채팅의 답변 형식이 바뀌면 가져오기가 실패할 수 있어요(그때는 "JSON만 다시 보내줘"로 요청하세요).

## 9-20. 링크 공고 형식 · 경력·학력 칸 · 사람인 입력용 정리 · 선택 요소 · AI 활용 강조

사람인에 올린 오픈한 공고 4개(FC팀 오프라인 MD, 러닝용품·뷰티 MD, 오즈키즈 마케팅 파트장, 글로벌팀 아마존)의 **포지션 상세**를 보고 맞춘 기능이에요. 실제 공고에서 포지션마다 달라지는 글은 모집요강 표의 "포지션 상세" 칸 하나였고, 경력·학력·근무형태·자격요건·우대사항은 사람인의 다른 칸에 따로 입력하고 있었어요.

**공고문(포지션 상세) 형식**
- AI 초안과 JD 템플릿 8종이 **링크 공고 형식**으로 나와요: 맨 위 **소개 문장**("그로잉업팀 아기동백 소속으로 …합니다") + 대괄호 없는 소제목 3개(`이런 일을 함께해요` · `이런 분이었으면 좋겠어요` · `이런 경험이 있다면 더 좋아요`). 예전의 네 번째 구역(이런 분과 함께하고 싶어요)과 맺음 문장, 본문 맨 위 "- 경력:" 줄은 없어요.
- 공고 만들기의 **"공고문에 넣을 요소"** 체크로 켜고 끌 수 있어요: **소개 문장**(기본 켬) · **성장 경험 구역**("○○팀에서 얻을 수 있는 성장 경험" 3~4개 항목, 글로벌팀 공고처럼) · **맺음 문장**. AI 초안에 적용돼요. 템플릿은 소개 문장이 들어 있고, 성장 경험 구역이나 맺음 문장은 템플릿 수정에서 직접 덧붙일 수 있어요.

**경력·학력 칸**
- 공고 만들기에 **경력**·**학력** 칸이 있어요(사람인의 "핵심 정보" 칸에 넣을 값, 둘 다 40자 이내, 비워 둘 수 있어요). 입력 칸을 누르면 `신입`, `경력무관(신입포함)`, `경력 3년 이상`, `대졸(4년제) 이상` 같은 추천 목록이 나와요.
- **포지션 상세에는 연차를 안 써도 돼요.** AI에게도 본문에 연차 숫자를 쓰지 말라고 하고, 연차는 이 칸 하나로만 관리해요. (사람인 공고 중 핵심 정보 "경력 2년 ↑"인데 상세에는 "3년 이상"이라고 적힌 경우처럼, 두 곳의 연차가 어긋나는 일을 막으려는 거예요.)
- AI 초안과 JD 템플릿은 경력을 **추천값**으로 경력 칸에 넣어 줘요. 칸 아래에 "추천값이에요 — 맞아요" 안내가 보이고, 고치거나 "맞아요"를 누르면 확인한 것으로 봐요. **사람이 먼저 쓴 경력은 추천값이 덮어쓰지 않아요.** 초안 3가지(A·B·C안)를 바꿀 때 확인하지 않은 추천값은 고른 안의 추천값으로 바뀌어요.
- 확정할 때 경력 칸이 비었거나 추천값을 확인하지 않았으면 확인창이 떠요(공고 점검 경고와 한 확인창으로 합쳐요). **막지는 않아요.**
- 확정된 공고의 경력·학력은 이력서 평가 글 끝에 `[사람인 핵심 정보]`로 덧붙어요. 학력은 "대졸(4년제) 이상" 같은 조건만이고 학교 이름은 평가에 쓰지 않아요.

**AI 활용 강조**
- 체크하면 AI 초안이 "이런 분이었으면 좋겠어요"에 AI 툴 활용 능력을, "이런 경험이 있다면 더 좋아요"에 ChatGPT·Claude·Gemini 등을 실무에 활용해 본 경험을 포지션에 맞게 넣어요. JD 템플릿으로 채울 때도 요건·우대 구역 끝에 한 줄씩 넣어요(소제목이 없는 템플릿이면 넣지 않아요).
- 공통 안내의 **[지원 방법] 구역 끝에 "AI를 이용한 작업 사례를 첨부해주세요. (1건 이상)"** 줄이 붙어요(공통 안내를 직접 고쳐서 [지원 방법] 구역이 없으면 붙이지 않아요). 기본은 꺼짐이에요.

**사람인에 붙여넣기**
- **"포지션 상세만 복사"**: 공고문에서 모집 개요와 공통 안내를 빼고 포지션 상세만 복사해요. 기존 "복사하기"는 **"공고 전체 복사"**로 이름을 바꿨어요(잡코리아·사람인에 통째로 붙일 때). 예전 형식으로 저장한 공고는 대괄호·네 번째 구역을 빼고 "- 경력: 3년 이상"을 "- 경력 3년 이상인 분"으로 바꿔서 복사해요. `[입력]` 표시가 남았거나 소제목 3개가 모두 없으면 복사 전에 확인창이 떠요(취소하면 복사하지 않아요).
- **"사람인 입력용 정리"**(포지션 상세 복사 버튼 아래의 접이식 상자): 경력·학력·근무형태·급여·근무일시·근무지역·자격요건·우대사항·포지션 상세 9칸을 칸별 **복사 버튼**과 함께 보여줘요. 위에서 고친 내용(저장 전 포함)이 그대로 반영돼요. 필요한 칸이 비어 있으면 "입력 필요" 배지와 "비어 있는 칸: …" 안내가, 선택 칸(급여·근무일시·우대사항)이 비어 있으면 "없음" 배지가 나와요. 자격요건·우대사항 칸은 사람인 형식(줄마다 `- `)으로 나와요. 급여·근무일시는 공통 안내의 줄에서 읽어요.
- 복사가 막힌 환경에서는 읽기 전용 글칸에 보여 줘서 직접 복사할 수 있어요. 이 기능들은 저장하지 않는 읽기 전용이라 **"보기" 권한만 있어도** 쓸 수 있어요(AI 초안은 "수정" 권한이 필요해요).

**알려진 한계**
- 실제 AI가 첫 줄 `경력 추천: …` 형식을 그대로 따르는지는 가짜 AI로만 확인했어요. 따르지 않으면 경력 칸이 빈칸이 될 뿐 오류는 아니에요.
- 사람인에 올린 공고를 앱이 읽어 오지는 않아요(기존 공고 가져오기는 없앴어요). 공고는 앱에서 만들고 확정한 뒤, 사람인에는 위의 칸별 복사로 옮기세요. 확정한 공고가 앱에 쌓이면 다음 공고를 만들 때 같은 팀의 지난 공고가 문체와 구성의 참고가 돼요.
- 템플릿 본문을 직접 고칠 때 소제목 3개와 요건 항목 1개 이상, `{{team}}`·`{{brand}}` 외의 `{{…}}` 금지만 검사해요.


## 9-21. 면접 관리 탭 · 면접 질문 추천 · 답변 전송 · 서류 체크리스트 (노션 "채용 문항" 표 기반)

노션 지원자 카드마다 들어 있는 **"채용 문항" 표**(No·전형·질문·기준·답변·점수)의 표준 문항을 앱에 옮겼어요. 면접 문항 28개(필수 15·선택 13, 그중 면접 시작 인사 3개)와 서류심사 문항을 기준으로 해요. 앱 안의 문항은 노션 표를 한 번 복사한 것이라, **노션 문항을 고쳐도 앱에는 자동으로 반영되지 않아요**(고치고 싶으면 알려주세요).

**면접 관리 탭** (이력서 검토 바로 옆)
- 위쪽 지원자 목록은 **예전 "지원자 관리"와 같은 화면**이에요(9-9, 9-12). 팀·면접상태(기본: 서류합격·면접 예정·과제)·이름으로 거를 수 있고, 지원자 줄의 **"면접 질문·답변"**을 누르면 아래에 그 지원자의 면접 화면이 열려요. 노션과의 **면접 일정 비교·맞추기**, **📨 면접 문자·📅 일정 연동**, 면접상태·면접 확정도 모두 이 화면에서 해요. 이력서 평가 요약(노션 카드에 앱이 남긴 기록)은 "이력서 평가 요약 보기"로 펼쳐 볼 수 있어요.
- 같은 화면을 **문자 보내기 탭 → 면접 일정 → "상세" → "면접 질문 추천"**에서도 쓸 수 있어요(일정의 이름·연락처로 노션 지원자를 찾아요).
- 권한: 면접 관리 **탭은 이력서 "보기" 권한**이 있으면 보여요(예전 지원자 관리와 같아요). 질문 만들기·답변 전송·질문 기록은 **면접 일정 수정 또는 이력서 수정** 권한 중 하나가 있으면 돼요. 면접 일정 권한만 있는 분은 면접 관리 탭은 안 보이지만, **문자 보내기 탭의 면접 일정 상세**에서 "면접 질문 추천"을 쓸 수 있어요.

**면접 질문 추천**
- 일정의 이름·연락처로 노션 지원자를 찾아요(연락처가 같은 사람을 우선하고, 동명이인이면 고르게 해요. 노션에 없으면 안내만 나와요).
- **"질문 추천받기"**를 누르면 오프닝(인사)·필수 질문·직무에 어울리는 추천 선택질문·**이력서 맞춤 질문**이 체크박스로 나와요. "OO님"에는 지원자 이름이 들어가요. 필수·맞춤·추천 선택은 처음부터 체크돼 있고, 필요 없는 건 체크를 풀면 돼요.
- 맞춤 질문은 노션 지원자 카드의 **평가 요약**(앱이 카드를 등록할 때 남긴 총평·강점·우려·면접에서 확인할 것)과 **지원직무·학력·주요경력**, 같은 팀에서 포지션 이름이 지원직무와 겹치는 **확정 공고의 요건**(이름이 안 맞으면 참고하지 않아요), 회사 인재상을 근거로 AI가 만들어요. 질문마다 "무엇을 확인하는지"와 "근거"가 붙어요. 앱 없이 등록한 카드처럼 평가 요약이 없으면 직무 기준으로만 만들고 안내해요.
- **패널만 열어서는 AI를 부르지 않아요.** 맞춤 질문은 "질문 추천받기"를 눌렀을 때만 만들어요. **"API 없이"**를 고르면 요청문을 복사해 Claude 채팅에 붙여넣고, 받은 답변(JSON)을 붙여넣어 가져와요(9-19와 같은 방식).
- **나이·결혼·가족·자녀·임신·종교·정치·출신 지역·외모·건강 같은 질문은 만들지 않아요.** AI에게 지시하는 것에 더해 **서버가 결과에서 한 번 더 걸러요**(걸러낸 개수를 알려줘요).
- **면접 점수 평균**: 질문·답변 화면 아래에 점수(⭐)를 매긴 질문들의 평균을 5점 만점으로 보여줘요(노션에서 불러온 점수도 포함). 화면에서만 계산하고 노션의 다른 칸(종합점수 등)은 건드리지 않아요. 지원자 줄의 "점수 · 추천"은 이력서 평가의 종합점수·추천이에요.
- **"선택한 질문 복사"**는 체크한 질문을 묶음별로 복사하고, **"노션 카드에 기록"**은 카드 본문에 "추천 면접 질문 (앱) · 날짜" 제목의 번호 목록으로 써요. 같은 카드에 이미 기록이 있으면 다시 기록할지 물어요. 질문은 참고이고 최종 질문은 면접관이 정해요.

**답변과 점수 적어서 노션에 전송** (면접 관리 탭·일정 카드 공통)
- 체크한 질문 아래에 **답변 칸과 점수(⭐1~5)**가 나타나요. 체크를 풀었다가 다시 켜도 적은 내용은 남아요.
- **"답변을 노션에 전송"**을 누르면 노션 지원자 카드 안의 **「채용 문항」 표**에서 같은 질문 행(문항 코드 `No`로 찾아요)의 **답변**과 **점수 선택** 칸에 써요. 답변·점수를 적은 질문만 보내요. 점수만 보내면 기존 답변은 그대로예요. 질문 오른쪽의 `점수 (5점 만점)`은 노션의 수식이라 건드리지 않아요.
- 표에 없는 질문(이력서 맞춤 질문)은 **새 행**으로 추가돼요(문항 코드 `C_01`, `C_02`…, 전형은 "선택질문", 기준·답변·점수 포함). 같은 질문을 다시 보내면 새 행을 또 만들지 않고 기존 행을 고쳐요.
- 노션 표에 **이미 적힌 답변**은 질문을 만들 때 미리 채워서 보여주고 "노션에 기록 있음"이 붙어요. 이 화면이 불러온 뒤 **노션에서 누가 먼저 고친 경우**에는 덮어쓰기 전에 어떤 질문인지 보여주며 확인해요(취소하면 노션은 그대로예요). 같은 내용을 다시 보내면 "변경 없음"으로 건너뛰어요.
- 카드에 「채용 문항」 표가 없거나 칸 이름·종류가 달라서 쓸 수 없으면 **카드 본문에 "면접 답변 기록 (앱)"**으로 대신 기록하고 이유를 알려줘요(이미 기록이 있으면 다시 기록할지 물어요). 노션 연결(통합)에 **카드 편집 권한**이 없으면 쓰지 못했다고 알려줘요.
- **평가 사유와 ⭐ 점수 기준표**: 질문마다 답변·점수 아래에 **"평가 사유(선택)"** 한 줄을 적을 수 있어요(1000자까지). 답에서 **관찰한 행동과 근거**로 적어요. 노션 「채용 문항」 표에는 사유 칸이 없어서 **"답변" 칸 안에 `답변 ⏎⏎[평가 사유] 사유`로 함께** 저장하고, 읽을 때는 앱이 답변과 사유를 나눠서 각 칸에 채워 줘요(노션에서 사람이 직접 쓴 답변은 그대로 답변으로 읽혀요). 답변만 고쳐 보내도 **노션에 있던 사유는 지워지지 않고**, 아무것도 바꾸지 않고 다시 보내면 "변경 없음"이에요. 노션에서 누가 먼저 고쳤으면 덮어쓰기 전에 물어봐요(답변과 사유를 합친 값으로 비교해요).
  - **나이·결혼·가족·병역·휴직 같은 주제가 사유에 있으면 기록하지 않고** 어떤 단어인지 알려줘요(채용 기록에 평가 근거로 남지 않게요). 한 번에 여러 질문을 보낼 때 하나라도 걸리면 전체를 보내지 않아요.
  - ⭐1·⭐2·⭐5를 고르고 사유가 비어 있으면 "사유를 적어두면 나중에 근거로 좋아요" 안내가 나와요(강제는 아니에요).
  - 점수 선택에는 짧은 뜻(미흡·약함·보통·좋음·매우 좋음)이 함께 보이고(마우스를 올리면 전체 뜻), 결과 위의 접이식 **"⭐ 점수는 이렇게 읽어요"**에 ⭐5~⭐1의 공통 의미가 있어요. 질문별 기준은 질문 아래의 "확인"과 "좋은 답·주의 신호"(9-23)를 같이 보세요. 점수는 참고이고 **합격·불합격은 사람이 정해요.**
  - 노션 채용 문항 표가 없는 카드는 카드 본문의 "면접 답변 기록"에 "평가 사유:" 줄로 남겨요.
- **보내지 않은 답변을 지키는 장치**: 보내지 않은 답변이 있을 때 지원자를 바꾸거나, 닫거나, 다른 탭으로 가거나, 질문을 다시 만들거나, 브라우저를 닫으려 하면 경고가 떠요. **이 앱은 답변을 서버에 저장하지 않아요.** 새로고침하면 보내지 않은 답변은 사라져요. 면접 중에는 중간중간 "답변을 노션에 전송"을 눌러 두세요.
- 답변은 한 질문당 6000자까지예요(노션 글자 한도 때문에 1900자씩 나눠 써요).

**서류 체크리스트** (이력서 평가 결과, 점수와 별개)
- 노션 서류심사표를 옮긴 점검표예요: 모든 문항 기입(`R_02`), 학력 사항 기재(`R_03`), 학업 완료 여부(`R_04`), 경력 기간 일치(`R_05`), 한 직장 1년 이상 재직(`R_06`), 일목요연함(`R_07`), 오타·표현(`R_08`), 포트폴리오(`R_09`). 항목마다 **확인됨 / 확인 필요 / 확인 불가**와 이력서 속 근거가 나와요.
- **점수·추천·합격 여부에 영향을 주지 않고**, 합격·불합격을 말하지 않아요. 이력서에서 알 수 없으면 "확인 불가"예요.
- **노션 서류심사표와 다른 점 (의도한 것)**: `R_01`(용모 단정하게 사진을 찍었는가)은 **AI 체크리스트에서 뺐어요.** AI가 사진·외모를 평가하지 않고, AI에게도 사진·외모·인상을 보지도 말하지도 말라고 지시해요. `R_03`·`R_04`(학력)는 "학력이 좋은가"를 판단하지 않고 이력서에 적힌 **사실**(학교·전공·졸업/중퇴)만 표시해요(학교 이름·명성으로 평가하지 않는 앱 원칙). `R_06`은 직장별 재직 기간만 사실대로 적고 짧은 재직의 이유는 추측하지 않아요(사유는 면접에서 확인).
- 노션 카드를 **등록할 때** 체크리스트를 카드 본문에 "서류 체크리스트 (앱 자동 점검)"로 기록해요(평가 결과 화면과 여러 이력서 한꺼번에 점수 보기 모두). **본문 쓰기에 실패해도 카드 등록은 성공으로 처리**하고 안내만 해요(다시 등록해서 카드가 중복되지 않게). 본문 쓰기에는 노션 연결(통합)의 **"콘텐츠 삽입" 권한**이 필요해요.
- "직접 채점"(AI 없이)으로 만든 결과에는 체크리스트가 없어요. "붙여넣기"는 Claude의 답변에 체크리스트가 있으면 같은 정리를 거쳐 들어와요.

**알려진 한계**
- 가짜 노션·가짜 AI로 확인했어요. 실제 AI가 체크리스트 JSON 형식을 그대로 따르는지, 맞춤 질문의 품질이 좋은지는 배포 후 몇 건 써 보며 확인해주세요(형식이 틀리면 체크리스트·맞춤 질문만 비고 오류는 아니에요).
- 공고의 "지원 방법" 안내 줄(경력 기간 정확 기재·모든 항목 기재 등)은 이번에 넣지 않았어요.
- 노션 문항 표에 있는 "1차 면접·2차 면접" 전형 구분은 쓰지 않아요(질문 은행은 필수·선택으로 나눠요). 서류심사 행(`R_01`~)에는 쓰지 않아요.
- 지원자 줄의 버튼(수정·📨·📅·면접 질문·답변·노션)은 칸이 좁아서 한 줄에 하나씩 쌓여요. 표 구조를 바꾸지 않으려고 이렇게 두었어요.
- 면접 관리 탭의 지원자 목록은 노션 「진행중 채용」 기준이라, 앱 밖에서 등록한 지원자도 보여요. 목록은 "더 보기"로 이어서 불러와요.
- "노션 카드에 질문 기록"(질문 목록을 카드 본문에 남기기)과 "답변을 노션에 전송"(표에 쓰기)은 별개예요.


## 9-22. 공고 상태 관리 · 공고 요건 ↔ 평가·면접 질문 연결

**공고 상태 (게시중·마감)**
- 공고 상태는 **작성 중 → 확정 → 게시중 → 마감**이에요. **확정**은 이력서 평가에 쓰는 공고라는 뜻이고(예전과 같아요), **게시중**은 확정된 공고에 **게시한 곳(채널)이 하나 이상** 있을 때, **마감**은 **마감 처리**했거나 **접수 마감일이 지났을 때**예요(접수 마감일 당일까지는 게시중이에요).
- **마감해도 이력서 평가는 계속 할 수 있어요.** 마감 뒤 도착한 지원서도 검토해야 해서, 마감한 공고에도 "평가에 사용"이 그대로 있어요.
- 공고 조회 목록에서 확정 공고의 **"게시·마감"** 버튼을 누르면 편집기가 열려요. 게시한 곳을 **최대 6개**까지 적어요(이름·공고 주소·게시일·지원자 수). 지원자 수는 사람인 같은 채널에서 확인한 숫자를 직접 적어요. 공고 주소는 `http://`·`https://`로 시작하는 주소만 받아요(`javascript:` 같은 주소는 거절해요). **"마감 처리"**를 누르면 오늘 날짜로 마감되고, **"마감 취소"**로 되돌릴 수 있어요. 저장하지 않은 내용이 있으면 닫거나 다른 공고를 열 때 확인해요.
- 목록의 상태 칸에는 배지, 확정일, 마감일, **게시한 곳 링크**, **노션 지원자 수**가 보여요. 노션 지원자 수는 노션 「진행중 채용」에서 **팀과 지원직무가 공고와 맞는 지원자**를 면접상태별로 세요(예: "노션 지원자 3명 (서류합격 2 · 1차 면접 예정자 1)"). **한계**: 지원직무 이름이 공고 포지션과 서로 포함되어야 같은 공고로 봐서, 앱 밖에서 직접 입력한 직무 이름은 안 맞을 수 있어요. 노션에서 최대 300명까지 읽어요.

**공고 요건 ↔ 이력서 평가**
- 공고문의 **"이런 분이었으면 좋겠어요"(필수 R1·R2…)**와 **"이런 경험이 있다면 더 좋아요"(우대 P1·P2…)**를 서버가 번호 붙은 **요건 목록**으로 정리해요(필수 10개·우대 8개까지, 모집 개요·공통 안내는 제외).
- 이력서 평가 때 이 목록을 AI에게 주고 **번호마다 판단**하게 해요. 결과는 번호로 맞춰 **공고의 원문 문장**으로 채워요. AI가 문장을 바꿔 쓰거나, 빼먹거나(빼먹은 요건은 "확인불가"), 목록에 없는 요건을 지어내도(버려요) 평가표가 공고와 어긋나지 않아요. 번호가 하나도 안 맞는 옛 형식 답변은 AI가 준 항목을 그대로 보여줘요.
- 평가 결과의 표 이름은 **"공고 요건 체크 (참고)"**로 바뀌었어요. 줄마다 **필수 R1 / 우대 P1** 배지가 붙고, 우대 항목의 "미충족"은 부족한 것처럼 보이지 않게 **빨간색이 아닌 회색**으로 보여요. 점수·추천과는 별개이고 탈락 기준이 아니에요. 일괄 점수 보기의 "필수 요건 충족 수"는 **필수만** 세요.
- 공고에 요건 구역이 없으면 예전처럼 AI가 공고문에서 필수 요건을 뽑아요. "직접 채점"은 요건 표를 만들지 않아요. 공고를 고치면 **다음 평가부터** 새 요건이 반영돼요(이미 한 평가는 그대로예요).
- **한계**: 실제 Claude가 "번호만 쓰기" 형식을 그대로 따르는지는 쓰면서 확인해 주세요(안 따르면 위의 안전장치로 예전 방식처럼 보여요).

**공고 요건 ↔ 면접 질문**
- 면접 질문 추천에서 지원자의 팀·지원직무에 맞는 **확정 공고가 연결되면**(같은 팀에서 포지션 이름이 겹칠 때), **"공고 요건 확인 질문"** 묶음이 맨 위에 나와요. 요건(필수·우대)마다 질문이 **하나씩** 만들어지고, 질문 아래에 **"요건: 공고의 원문"**과 **필수 R1** 배지가 보여요. 이력서에서 이미 확인된 요건도 "어떻게 했는지"를 묻는 질문이에요.
- 서버는 AI가 준 요건 번호가 **공고 목록에 있을 때만** 받고 요건 문장은 서버가 채워요. 같은 번호의 중복과 지어낸 번호는 버리고, 요건 순서대로 정렬해요. **나이·결혼·가족 같은 차별 주제는 맞춤 질문과 똑같이 걸러요.**
- 답변·점수를 적어 노션에 전송하면 맞춤 질문처럼 노션 「채용 문항」 표에 **새 행(C_nn)**으로 들어가고, 기준 칸에 `[필수 R1] 요건 원문`이 남아요. 면접 점수 평균에도 포함돼요.
- "API 없이"에서는 요청문에 요건 목록이 들어가고, 받은 답변을 붙여넣으면 요건별 질문도 가져와요(요청문을 만든 지원자의 공고 요건 번호를 써요).
- 공고가 연결되지 않은 지원자는 이 묶음이 없고 이전처럼 맞춤 질문만 나와요.

**알아두실 점 (오류 수정)**
- 달력에 없는 날짜(13월·0월·32일)를 API로 직접 보내면 서버가 400이 아니라 **500 오류**를 내던 문제를 고쳤어요(접수 기간, 지원자 면접일 저장에도 있던 문제예요). 화면의 날짜 입력칸은 이런 값을 만들지 않아서 보통은 드러나지 않았어요.

## 9-3. (참고) 사람인/잡코리아 이력서 자동 수집에 대하여

사람인·잡코리아는 기업회원용 대량 다운로드나 공식 API를 제공하지 않으며, 자동화된 접근(크롤링, 확장프로그램을 통한 자동 수집 등)은 각 사이트 이용약관상 제한될 수 있습니다. 본인 회사에 지원한 지원자 데이터라도, 자동 수집 도구를 만들기 전에 각 플랫폼의 이용약관을 확인하시길 권장합니다. 이 기능은 현재 이 앱에 포함되어 있지 않습니다.

## 10. 배포 (Render + 영구 디스크로 링크 발급받기)

로컬 컴퓨터를 켜두지 않아도 `https://앱이름.onrender.com` 같은 링크로 어디서나 접속하게 만드는 방법입니다. 발송 이력·면접 일정 데이터가 재시작 후에도 사라지지 않도록 **영구 디스크(유료, 월 $1부터)**를 함께 연결합니다.

1. **GitHub에 코드 올리기**: https://github.com 가입 → 새 저장소 생성 → 이 폴더의 파일을 업로드 (`.env` 파일은 올리지 않습니다)
2. **Render 가입**: https://render.com 가입 → "New" → "Web Service" → 방금 만든 GitHub 저장소 연결
3. **기본 설정**
   - Build Command: `npm install`
   - Start Command: `npm start`
4. **환경변수 등록** (Environment 탭에서 추가)
   ```
   SMSKO_USER_ID=문자코리아_아이디
   SMSKO_API_KEY=문자코리아_API_키
   SMSKO_SENDER=등록된_발신번호
   DATA_DIR=/data
   ```
5. **영구 디스크 추가** (Disks 탭 → Add Disk)
   - Mount Path: `/data` (반드시 위 `DATA_DIR` 값과 동일하게)
   - Size: 1GB면 충분합니다
   - 유료 플랜(Starter 이상)에서만 디스크 추가가 가능합니다
6. **배포**: "Create Web Service" 클릭 → 몇 분 후 `https://앱이름.onrender.com` 링크 생성됨
7. 문자코리아 "연동IP 등록" 페이지에서, 이 서버의 IP를 새로 등록해야 발송이 됩니다 (Render 서버 IP는 로컬 컴퓨터 IP와 다릅니다 — 배포 후 앱에서 문자를 한 번 보내보면 오류 메시지에 IP 관련 힌트가 나올 수 있고, 정확한 IP는 Render 대시보드나 문의를 통해 확인할 수 있습니다)

이렇게 하면 컴퓨터를 꺼도 링크가 항상 살아있고, 재시작되어도 `/data`에 저장된 이력·일정 데이터는 그대로 유지됩니다.

## 10-2. 배포 (Vercel + Upstash Redis로 링크 발급받기)

**이미 Vercel을 쓰고 계신 경우** 이 방법으로 배포하세요. Vercel은 파일 저장이 안 되는 구조라, 데이터 저장소로 **Upstash Redis**(Vercel Marketplace에서 설치하는 저장소, 별도 서버 설치 없이 프로젝트에 "연결"만 하면 됩니다 — Vercel의 기존 "Vercel KV"는 서비스가 종료되고 이 방식으로 대체되었습니다)를 함께 붙입니다. 코드는 이미 이 연동을 자동으로 감지해서 쓰도록 만들어져 있습니다 (환경변수만 연결하면 끝).

1. **GitHub에 코드 올리기**: https://github.com → 새 저장소 생성 → 이 폴더 업로드 (`.env` 제외). `vercel.json`이나 `api` 폴더는 필요 없습니다 — Vercel이 Express 앱을 자동으로 인식합니다
2. **Vercel에서 프로젝트 가져오기**: https://vercel.com 로그인 → "Add New" → "Project" → 방금 만든 GitHub 저장소 선택 → Import → 그대로 "Deploy" (Framework Preset이 자동으로 "Express"로 인식되면 그대로 두세요 — 억지로 "Other"로 바꾸지 마세요)
3. **Upstash Redis 만들기**: 프로젝트 대시보드 → "Storage" 탭(또는 "Integrations") → "Create Database"(또는 "Browse Marketplace") → **Upstash**(Redis) 선택 → 이름 정하고 생성
4. **프로젝트에 연결**: 생성 과정에서 방금 만든 프로젝트를 선택해 연결하면 `KV_REST_API_URL`, `KV_REST_API_TOKEN` (또는 `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN`) 환경변수가 **자동으로** 프로젝트에 추가됩니다 — 코드가 두 가지 이름 모두 인식하므로 어느 쪽이든 상관없습니다
5. **나머지 환경변수 추가** (프로젝트 → Settings → Environment Variables)
   ```
   SMSKO_USER_ID=문자코리아_아이디
   SMSKO_API_KEY=문자코리아_API_키
   SMSKO_SENDER=등록된_발신번호
   ```
6. **재배포**: Settings에서 환경변수를 추가한 뒤에는 Deployments 탭에서 "Redeploy"를 한 번 눌러줘야 새 환경변수가 반영됩니다
7. 배포가 끝나면 `https://프로젝트이름.vercel.app` 링크가 생깁니다
8. 문자코리아 "연동IP 등록" 페이지에 이 배포 서버의 IP를 등록해야 발송이 됩니다 (Vercel 서버 IP는 매번 달라질 수 있어서, 안내 문서의 "고정 아웃바운드 IP" 기능을 함께 확인해보시는 걸 추천드려요 — Vercel 대시보드에서 "고정 IP" 관련 설정을 찾아보시거나 필요하면 말씀해주세요)

> 참고: KV 연결 없이 배포하면 파일 저장 방식으로 자동 전환되긴 하지만, Vercel 환경에서는 재요청마다 파일이 사라지므로 **Redis 연결은 필수**입니다.

> **이전에 vercel.json이나 api 폴더를 GitHub에 올리셨다면 삭제해주세요.** Vercel이 Express 앱을 자동으로 인식하는 최신 방식으로 바뀌면서 더 이상 필요 없고, 오히려 있으면 자동 인식을 방해할 수 있습니다.

## 11. 고정 IP 프록시 연결하기 (Fixie 등)

Vercel/Render 같은 클라우드 플랫폼은 발신 IP가 고정되지 않아서, 문자코리아처럼 IP 등록이 필수인 API와 연동할 때 문제가 생길 수 있습니다. 이럴 때는 Fixie 같은 고정 IP 프록시 서비스를 거치면 해결됩니다.

1. https://usefixie.com 에서 앱을 만들면 고정 IP 2개와 프록시 URL이 발급됩니다.
2. 발급받은 두 IP를 문자코리아 "연동IP 등록" 페이지에 각각 등록합니다.
3. 배포 환경(Vercel/Render)의 환경변수에 아래처럼 추가합니다.
   ```
   FIXIE_URL=http://fixie:발급받은토큰@criterium.usefixie.com:80
   ```
4. 코드는 `FIXIE_URL`이 설정되어 있으면 자동으로 문자코리아 API 호출을 이 프록시를 거치도록 되어 있습니다 (별도 코드 수정 불필요). 설정되어 있지 않으면 지금처럼 직접 호출합니다.
5. 재배포 후 `/api/smsko-check`로 접속하면 결과에 `"usingProxy": true`가 표시되면 정상 적용된 것입니다.

## 참고: 문자코리아 API 동작 방식

- 발송 요청마다 서버가 먼저 `/api/v1/token`으로 접속해 임시 인증 토큰(accessToken)을 발급받고, 그 토큰을 `/api/v1/message` 요청의 Authorization 헤더에 담아 실제 문자를 보냅니다. (앱 사용자는 이 과정을 신경 쓸 필요 없이 자동으로 처리됩니다.)
- 본문이 90byte(한글 약 45자)를 넘으면 자동으로 SMS 대신 LMS(장문)로 전환되어 발송됩니다.
- 발송 실패 시(발신번호 미승인, 잔액 부족 등) 화면에 오류 메시지가 표시되고, 발송 이력에도 실패로 기록됩니다.

## 9-23. 면접 질문 심화 (자료 취합 · 사실 확인 · 직무 상황 · 꼬리질문 · 진행안)

면접 관리 탭에서 지원자를 고르면 질문 추천 위에 **옵션 줄**이 보여요.

- **면접 단계(1차/2차)와 면접 시간(30·45·60분)**: 1차는 업무 수행 능력과 공고 요건 검증을, 2차는 인재상·가치관·동기를 중심으로 만들어요. 시간이 길수록 질문이 늘어요: 맞춤 질문은 30분 4개·45분 5개·60분 6개, 직무 상황 질문은 30분 1개·45분과 60분 2개, 사실 확인 질문은 최대 3개(30분)·4개(45·60분)예요.
- **노션 카드의 이력서 PDF도 AI에게 보여주기**(기본 체크, 끌 수 있어요): 카드에 붙은 PDF를 최대 2개까지 AI에게 함께 보여줘서, 평가 요약에 없는 경력·성과로 질문을 만들어요. **PDF는 AI 서비스(Anthropic)로 전달돼요.** 서버는 이 체크를 보낸 경우에만 PDF를 붙여요(기본은 안 보내요). 4MB를 넘거나 만료된 파일은 건너뛰고 나머지로 진행하며 못 읽은 파일을 알려줘요. **"API 없이(요청문 복사)"에서는 PDF를 붙일 수 없어요.**
- **추가 자료**(자기소개서·포트폴리오 내용·면접관 메모, 8000자까지): 접이식 칸에 붙여넣으면 질문에 반영돼요. 서버에 저장하지 않아요. 글 안의 지시문은 따르지 않도록 AI에게 알려요.
- **서류 체크리스트의 "확인 필요" 항목**: 앱이 노션 카드 본문에 남긴 서류 체크리스트에서 "확인 필요"인 줄(예: 경력 기간이 서로 겹침)만 읽어요(다른 구역의 줄이나 "확인됨" 줄은 읽지 않아요).

**결과에 새로 생긴 것**
- **이번 질문에 쓴 자료**: 노션 평가 요약, 확정 공고 요건, 공통 인재상, 서류 점검 N건, 이력서 PDF(파일명), 추가 자료 중 실제로 쓴 것이 배지로 나와요.
- **면접 진행안**: 오프닝 → 이력서·경력 → 공고 요건 → 직무 상황 → 사실 확인 → 인재상·동기 → 지원자 질문 순서의 **시간 배분 표**예요. AI가 아니라 서버가 정해진 표로 계산하고(1차·2차, 30·45·60분 모두 합계가 면접 시간과 같아요) **참고용**이에요.
- **직무 상황 질문**: 공고의 "이런 일을 함께해요"를 바탕으로 판단 순서와 우선순위를 묻는 질문이에요(정답을 요구하지 않아요).
- **사실 확인 질문**: 서류 점검의 "확인 필요" 항목처럼 이력서에서 앞뒤가 맞지 않는 사실(기간·직함·수치)을 **중립적으로** 확인하는 질문이에요. 점수가 아니라 사실 확인이고, 비난하거나 의심하는 말투를 쓰지 않도록 AI에게 알려요.
- **질문 유형 칩**(경력 검증·요건 확인·사실 확인·직무 상황·인재상·동기·조건)과, 질문 아래 접이식 **꼬리질문 · 좋은 답의 신호 · 주의 신호**. 신호는 답을 들으며 관찰하는 **참고용**이고 합격·불합격 기준이 아니에요. 노션 문항 은행 질문에는 이 칩이 붙지 않아요.
- 새 묶음 질문도 다른 질문처럼 체크해서 **답변·점수(⭐)를 적고 노션 「채용 문항」 표에 새 행으로 전송**할 수 있고, **"노션 카드에 질문 기록"**과 **복사**에는 유형·꼬리질문·좋은 답·주의가 함께 들어가요. 면접 점수 평균에도 포함돼요.
- **"API 없이"**: 요청문에 새 형식과 자료가 들어가고, 받은 답변을 붙여넣으면 사실 확인·직무 상황 질문도 가져와요.

**안전**
- 나이·결혼·가족·종교·외모 등에 더해 **병역·군 복무·휴직·경력 공백 사유**도 질문 금지 목록에 있어요. 맞춤 질문뿐 아니라 사실 확인·직무 상황·**꼬리질문·좋은 답/주의 신호에도** 같은 필터가 적용되고, 걸러진 개수는 "N개는 뺐어요"로 알려줘요(사실 확인 질문이 이런 주제를 건드리지 않게 하려는 장치예요).
- 질문과 신호는 **참고**예요. 최종 질문과 평가는 면접관이 정해요.

**한계**
- 실제 Claude가 새 JSON 형식(유형·꼬리질문·신호·사실 확인·직무 상황)을 그대로 따르는지는 쓰면서 확인해 주세요. 못 따르면 해당 항목만 비고 오류는 아니에요.
- PDF를 붙이면 AI 호출이 느려지고 비용이 늘어요. 배포 환경의 응답 시간 제한에 걸리면 "AI가 맞춤 질문을 만들지 못했어요"가 나올 수 있어요. 그럴 땐 PDF 체크를 끄세요.
- 질문별 **점수 기준표(⭐ 의미)와 평가 사유 입력**은 아직 없어요. 좋은 답/주의 신호가 그 일부 역할을 해요.

## 9-24. 파일로 공고·채점 결과 가져오기

이 대화나 다른 곳에서 정리한 **공고**와 **채점한 점수**를 앱 화면에 바로 띄우는 기능이에요. 읽을 수 있는 형식은 **JSON 파일(.json)**이에요(`.md`나 PDF는 안 돼요). 앱은 이력서 PDF와 점수 결과를 저장하지 않으니, 가져온 점수도 화면에만 있다가 닫으면 사라져요(노션에 기록한 사람만 남아요).

**공고 파일 가져오기** (공고 관리 → 공고 만들기, "공고 조회" 위쪽의 "📂 공고 파일 가져오기")
- 파일의 `postings` 목록에 있는 공고를 직접 만든 것과 **같은 검증**을 거쳐 저장해요(한 번에 20개까지). 확인창에서 취소하면 아무것도 저장하지 않아요.
- **같은 팀·같은 포지션(·브랜드)이 이미 있으면 건너뛰고** 덮어쓰지 않아요. 잘못된 공고(없는 팀, 위험한 게시 주소, 너무 짧은 확정 공고)가 섞여 있어도 나머지는 저장하고, 결과 목록에 공고마다 "저장했어요 / 건너뛰었어요 / 사유"와 **공고 점검 건수**(수정 필요·확인 필요)가 나와요.
- **작성 중(`draft`)으로 가져온 공고는 이력서 평가의 "평가할 공고" 목록에 나오지 않아요.** 평가 목록은 **확정된 공고만** 보여줘요(버그가 아니라 "확정 전" 상태예요). 그래서 세 곳에서 알려줘요: ① 가져오기 결과의 공고마다 **"지금 확정"** 버튼(누르면 공고 점검 건수와 `[입력]` 빈칸 안내가 나오는 확인창 → 확정하면 평가 목록에 바로 나와요), ② 이력서 검토 화면의 "평가할 공고" 아래 **"확정하지 않은 공고 N개는 여기에 안 나와요: 공고 이름…"** 안내와 **"공고 만들기로 이동"** 버튼(확정하지 않은 공고가 있을 때마다 보여요). ③ **공고 조회 목록**에서 작성 중인 공고 줄에는 "평가에 사용" 대신 **"확정"** 버튼이 있어요(같은 확인창을 거쳐 바로 확정돼요, 확정하면 그 줄이 "평가에 사용"으로 바뀌어요). 공고를 "수정"으로 열어 **"✅ 공고 확정"**을 눌러도 같아요.
- `[입력]` 빈칸(공통 안내의 반환·보관 안내, 9-14)은 **이력서 평가에는 영향이 없어요**(평가는 공고의 필수·우대 요건을 써요). 하지만 사람인·잡코리아에 올리기 전에는 채워야 해요. "지금 확정"의 확인창이 이 점을 알려주고, 확정은 담당자가 정해요. 공고문이 너무 짧거나 형식이 틀리면 서버가 확정을 거절하고 이유를 알려줘요.
- 파일 한 항목의 칸: `team`, `position`, `brand`, `career`, `education`, `workplace`, `employmentType`, `months`, `applyStart`, `applyEnd`, `jd`, `status`(draft/confirmed), `channels`(게시한 곳). 직접 만드는 것과 같은 규칙이 적용돼요.

**채점 결과 파일 가져오기** (공고 관리 → 이력서 검토 → "여러 이력서 한꺼번에 점수 보기"의 "📂 채점 결과 파일 가져오기")
- 먼저 위의 **"평가할 공고"를 고르고**(확정된 공고만 돼요) 파일을 올리면, 파일의 사람들이 **점수 표에 "가져온 채점 결과 (이력서 PDF 없음)"**로 들어와요. 이후는 직접 평가한 줄과 같아요: "점수표" 보기, **"선정" → "노션에 기록하기"**, 줄별 "서류 합격 확정", 면접 문자.
- 파일에는 사람마다 `candidate`(이름·연락처·학력·경력), `scores`(영역별 점수), `comments`(근거), `summary` 등을 적어요. **총점과 검토 우선순위(추천)는 앱이 영역 점수로 다시 계산해요.** 파일에 총점·추천을 적어도 무시해요.
- 한 번에 60명까지 가져올 수 있어요. 점수가 영역 범위(예: 유사 경력 0~30)를 벗어나거나 빠졌거나 이름이 없으면 **그 사람만** 가져오지 않고 사유를 알려줘요(나머지는 가져와요). 파일의 `profile`(경력직/신입직)이 공고의 평가표와 다르면 가져오지 않고 "같은 종류의 공고를 골라주세요"라고 알려줘요.
- **공고 요건 체크는 파일의 요건 번호(R1·P1…)가 고른 공고의 요건 번호와 맞을 때만** 보여줘요. 안 맞으면 비워 둬요(안 맞는 요건에 "확인불가"를 잔뜩 채우지 않으려고요).
- **가져온 결과는 앱이 이력서를 읽은 게 아니라서, 비어 있는 칸을 "이력서에 없어요"라고 말하지 않아요.** 파일에 값이 없으면 "**가져온 결과에는 이 정보가 없어요. 이력서에서 직접 확인하세요**"(재직 여부·희망 연봉·전공 관련성)와 "**가져온 결과에는 근거가 없어요**"(영역별 평가 근거)로 보여줘요. 값이 있으면 값을 보여주고 "가져온 결과에 적힌 내용이에요"라고 알려줘요. **앱이 AI로 직접 평가한 결과는 예전 그대로**(AI가 읽었는데 없을 때만 "이력서에 없어요")예요. 파일의 칸: `interviewInfo`(`desiredSalary`=희망 연봉, `availability`=재직 여부·입사 가능 시기), `majorFit`(`relation`=직무 관련·일부 관련·관련 낮음·확인불가, `note`), `comments`(영역별 근거: `similar`·`fit`·`impact`·`values`·`years`·`edu`), `summary`(서류 총평), `concerns`(면접에서 확인할 점), `requirements`(`id`·`status`·`evidence`).
- 같이 드린 채점 결과 파일(`채점결과_*_가져오기.json`)에는 **희망 연봉(이력서에서 읽은 값, 25명 전원)과 재직 표시(이력서에 "재직중"이 적힌 5명)**, 요건 체크, 유사 경력·성과·공고 적합도의 근거, 서류 총평, 면접에서 확인할 점이 들어 있어요. 연차·학력 근거는 일부만, **인재상 근거는 비어 있어요**(점수는 있지만 사람별 근거 문장을 따로 쓰지 않았어요). 이 근거 글은 앱이 이력서를 다시 읽은 게 아니라 이 대화에서 정리한 채점 근거 문서(`이력서_채점결과_*.md`)를 옮긴 거예요.
- **이력서 PDF가 없어서** 노션에 기록할 때 PDF는 붙지 않아요(줄에 안내가 나와요). 필요하면 노션 카드에서 직접 붙이거나, 같은 PDF를 이력서 검토에서 다시 올려 평가하세요.
- **개인정보 주의**: 채점 결과 파일에는 이름·연락처·경력 요약이 들어 있어요. 가져온 뒤에는 파일을 지우고, 다른 사람에게 보내지 마세요.

**권한과 한계**
- 두 가져오기 모두 **이력서 검토 "수정" 권한**이 필요해요(Google 로그인 모드. 비밀번호 모드에서는 로그인하면 모두 쓸 수 있어요). 권한 표에서 빠진 경로는 Google 모드에서 소유주만 쓸 수 있게 닫혀요.
- 가져온 점수는 **앱이 AI로 평가한 점수가 아니라 파일에 적힌 점수**예요. 같은 이력서를 앱에서 AI로 평가하면 점수가 다를 수 있어요.
- 점수 표는 한 번에 160줄까지 보여요(넘으면 "목록 비우기" 후 다시 가져오세요). **같은 공고에 같은 이름(후보자)을 다시 가져오면 마지막 파일의 결과로 바뀌어요**(같은 파일을 두 번 가져와도 줄이 늘지 않아요). 이미 노션에 기록한 줄은 바꾸지 않아요. 같은 이름이라도 다른 공고에 가져오면 따로 줄이 생겨요.

## 9-25. 승진·경력 관리 (직원 경력과 승진 검토)

채용 앱과 별개로, **재직 직원의 경력을 직접 입력해 두고 승진 검토 대상을 계산**하는 메뉴예요. 직원 경력 엑셀(`직원경력_승진관리_누적경력합산`)의 계산 규칙을 그대로 옮겼어요. 처음 데이터는 엑셀의 46명을 담은 `직원경력_가져오기.json`으로 한 번에 넣어요.

**누가 볼 수 있나 (중요)**
- 직원 이름·생년월일·직급·경력이 들어가는 **인사 정보**예요. 그래서 새 메뉴 **"승진·경력 관리"**가 따로 있고, **Google 로그인 모드에서는 소유주가 권한 관리에서 사용자마다 "보기/수정"을 줘야** 탭이 보여요(처음에는 아무도 없어요, 소유주만 자동으로 가져요). 비밀번호 모드에서는 로그인하면 모두 쓸 수 있어요.
- 표에는 생년월일이 나오지 않고, 직원을 눌러 수정할 때만 보여요. 직원 삭제 로그에는 이름을 남기지 않아요.

**계산 규칙 (엑셀과 같아요)**
- **인정 타사 경력(개월) = 직무 연관성 높음 × 70% + 낮음 × 20%** (인정률은 설정에서 바꿀 수 있어요)
- **누적 경력(년) = 당사 근속(입사일~오늘) + 인정 타사 경력 ÷ 12**. 근속은 엑셀 `YEARFRAC(…,1)`(실제/실제)와 같은 값이에요(무작위 날짜 408개를 엑셀 계산과 대조했어요). 합친 뒤 소수 둘째 자리에서 한 번만 반올림해요.
- **입사 시 인정 직급(참고)**: 인정 경력 48개월 미만 사원 / 84 미만 대리 / 132 미만 과장 / 180 미만 차장 / 그 이상 부장 검토. 실제 입사 직급은 인사 담당자가 확정해야 해요.
- **승진 기준 표(처음 값)**: 사원 4년(현 직급 최소 4년), 대리 7년(3년), 과장 11년(4년), 차장 15년(4년). 부장·이사·실장·대표이사는 기준이 없어 **"별도 심사"**예요. 표는 화면의 "승진 기준·판정 방식"에서 고칠 수 있고, 직원이 쓰는 직급은 지울 수 없어요.
- **승진 판정**: 직급 비어 있음 → 직급 확인 / 기준 없는 직급 → 별도 심사 / 입사일·기준 없음 → 정보 확인 필요 / 그 외 누적 경력 ≥ 다음 승진 기준이면 **승진 검토 대상**, 아니면 **기준 미달**. 판정 칩 옆에 "누적 경력 16.16년 / 기준 11년 충족 · 현 직급 근속 12.66년 / 최소 4년 충족" 같은 **세부 사유**가 나와요.
- **판정 방식 (직접 정해야 해요)**: 엑셀 `사용방법` 시트는 "누적 경력과 현 직급 최소 근속을 **모두** 충족해야 한다"고 쓰는데, 엑셀의 실제 판정 수식은 **누적 경력만** 비교해요. 앱은 설명대로 **둘 다 보는 것을 기본**으로 하고(누적은 충족이지만 근속이 모자라면 **"근속 부족"**), 화면의 체크 하나로 엑셀 수식처럼 "누적 경력만" 보게 바꿀 수 있어요. **엑셀 46명 기준으로 결과가 크게 달라요**(2026-10-29에 계산한 값이고, 날짜가 지나면 조금씩 바뀌어요): 누적 경력만 보면 승진 검토 대상 8명, 둘 다 보면 1명(근속 부족 7명).
- 기준을 **소수 둘째 자리 반올림 값**으로 비교해서(엑셀과 같아요), 기준보다 며칠 모자라도(3.995년 이상) 충족으로 나올 수 있어요. 예: 사원 기준 4년에 하루 모자란 사람도 4.00년으로 반올림돼요.

**직원 등록·수정·삭제**
- **"+ 직원 등록"**: 이름·입사일·현재 직급은 꼭 필요하고, 사번·영어 이름·생년월일·고용형태·근무지·현 직급 발령일(비우면 입사일과 같아요)·비고는 선택이에요. 입사일이 미래이거나 달력에 없는 날짜, 사번 중복은 막아요.
- **타사 경력은 직접 입력**해요(이력서 경력): 회사·**경력 개월 수**·**직무 연관성(높음/낮음)**·메모를 항목마다 적고, 위쪽에 인정 경력이 **입력하는 대로 미리 계산**돼요(최대 30개). 엑셀에서 가져온 직원은 "높음 합계"와 "낮음 합계" 항목 두 개로 들어와요. 직원을 눌러 회사별로 나눠 다시 적어도 돼요.
- **수정**: 직원 줄의 "수정"에서 어느 칸이든 고칠 수 있어요(직급 변경과 발령일 갱신 포함). 저장하지 않고 닫으면 확인해요.
- **퇴사자 삭제**: 줄의 "삭제"를 누르면 **직원 이름을 그대로 입력**해야 지워져요(서버도 한 번 더 확인해요). 지우면 **되돌릴 수 없어요.** 필요하면 지우기 전에 엑셀 등으로 따로 보관하세요.
- **파일로 가져오기**: "📂 직원 파일 가져오기(.json)". 같은 사번이 있으면 건너뛰고, 일부가 잘못돼도 나머지는 등록해요.

**목록**: 위쪽 칩(전체·승진 검토 대상·근속 부족·별도 심사·기준 미달, 누르면 거르기), 이름·사번 검색, 직급·근무지·판정 필터, 정렬(누적 경력 많은 순·입사일 빠른 순·이름순·직급순)이 있어요.

**한계**
- 승진 **결정**을 하지 않아요. 직원이 승진해도 직급과 발령일은 사람이 수정해서 바꿔야 해요(자동 승진 처리 없음).
- 오늘 날짜는 **한국 시간** 기준이에요. 직원은 최대 500명, 한 직원의 타사 경력은 30개예요.
- 이 데이터는 앱의 저장소(Upstash)에 저장돼요. 백업이 필요하면 엑셀 원본을 보관하세요(이 앱은 직원 파일 내보내기를 아직 지원하지 않아요).

## 9-26. 이력서에 적힌 인적사항 보기 (점수·추천에는 쓰지 않아요)

점수 표에서 지원자의 **성별·나이·학교·전공·총경력·연봉**을 바로 볼 수 있어요. 이력서에 **적힌 그대로** 옮겨 보여주는 정보이고, **점수·추천·근거·강점·우려에는 쓰지 않아요.**

**어디에 보여요**
- **점수 표의 각 줄**: 이름 바로 아래에 `성별 · 나이 · 학교 · 전공(학력 구분) · 총경력 · 연봉(희망·현재)`이 라벨과 함께 보여요. 이력서에 없는 값은 `-`로 보여서 "못 읽음/없음"이 구분돼요. 학교 이름이 없고 전공만 있으면 학교는 `-`, 전공은 전공 칸에만 보여요(전공을 학교처럼 보이게 하지 않아요).
- **"점수표"(상세)**: 맨 위에 전체 표(성별·나이·학교·전공·학력 상태·총경력·연봉·이메일·주소)와 "이력서에 적힌 정보예요. 점수·추천에는 쓰지 않아요" 안내가 있어요.
- **이력서 한 건을 평가하는 결과 화면**: 같은 표가 공고 이름 아래에 나와요.
- 좁은 화면(휴대폰)에서는 지원자 칸이 위아래로 펼쳐져서 이름과 칩이 폭을 다 써요.

**어떻게 읽어요**
- AI가 이력서에서 적힌 그대로 옮기고(추측 금지), 없으면 빈 칸이에요. **나이는 이력서에 적힌 값을 우선**하고, 없으면 서버가 계산해요: 생년월일 전체가 있으면 만 나이(`만 37세 (1989년생)`), 생년만 있고 이력서에 나이도 적혀 있으면 그 값(`1989년생 · 이력서 기재 36세`), 생년만 있으면 올해 기준 연 나이(`1989년생 (37세)`), 나이만 적혀 있으면 `37세 (이력서 기재)`. 이력서에 적힌 나이는 쓴 시점의 나이라서 계산값과 1살 차이가 날 수 있어요. 존재하지 않는 날짜·미래·너무 옛날 값은 버려요.
- 총경력은 이력서에 합계가 적혀 있으면 그대로, 없을 때만 직장별 기간을 더해 "(기간 합산)"이라고 표시해요.
- **주민등록번호 모양(`######-#######`)은 어느 칸에 섞여 와도 지우고**, HTML 태그도 지워요. 길이가 긴 값은 잘라요. 성별은 남·여로 읽히는 값만 받아요. **사진·혼인·가족관계는 읽지도 보여주지도 않아요.**
- **점수와 분리**: 점수는 영역별 점수의 합으로만 정해지고 인적사항은 계산에 들어가지 않아요. 영역 점수가 같고 나이·성별·학교·연봉만 다른 사람들의 총점·추천이 똑같은지 시험으로 확인해요. 학력·전공 영역은 이전과 같이 학교 이름·명성·학점을 점수에 쓰지 않아요.
- **채점 결과 파일 가져오기**: 파일 안 `personal`(gender, birthDate, ageText, school, major, degree, totalCareer, totalCareerSource, desiredSalary, currentSalary, email, address)도 같은 규칙으로 정리해서 보여줘요. `personal`이 없으면 모든 칩이 `-`로 보여요.
